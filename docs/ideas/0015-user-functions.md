# 0015. Пользовательские функции из простейших

**Статус:** частично реализовано
**Сложность:** высокая

## Текущее состояние

Базовый вариант уже работает в C++:

- блоки `function/in/out/use/body/end` читаются из `.lvl` и пишутся обратно;
- параметры, выходы, временные переменные и деструктуризация `q, r = ...`;
- фиксированные выходы и один поток `T...`;
- `take`, `drop`, `first`, `rest`, `count` в теле;
- перегрузки по типам входов и `use`-алиасы;
- `--function` — консольный редактор с `validate`, `test` и `save`;
- сохранённый `.fn` можно подключить к уровню строкой
  `function <имя> file <файл>`;
- случайность и транзитивная стабильность поддерживаются решателем.

Пока это интерпретатор: структура блока проверяется при загрузке, а типы и
домены — во время вычисления. Полноценная компиляция в AST со статической
проверкой типов остаётся следующим этапом. `sort`/`shuffle`, `if`/`bool` и
несколько потоков пока не реализованы; `abs`/`not` остаются бинарными.

## Суть

Игрок или автор уровня собирает новую функцию из простейших:

```text
function divmod
  in a: integer
  in b: integer
  out q: integer
  out r: natural
  body
    q = div a b
    r = mod a b
end
```

Это развитие Java-прототипа (`Function`, `FunctionMakerPanel`), но с
человекочитаемым сохранением и явными типами входов/выходов.

## Формат блока

```text
function <имя>
  description <текст>
  in  <имя>: <тип>
  out <имя>: <тип>
  use <алиас> = <функция> <типы> -> <типы>
  body
    <имя> = <выражение>
    ...
end
```

- `in`/`out` можно повторять; у каждого параметра и выхода есть имя.
- `out <имя>: T...` — поток: 0+ значений типа `T`. Поток только один и
  только последним.
- `description` необязателен; для известных функций описание берётся из
  `data/functions.txt`.
- `body` — последовательность иммутабельных связываний, как `let*`.
- Выход обязан быть присвоен ровно один раз; временные переменные могут
  использоваться повторно без перевычисления.
- Допускается деструктуризация: `q, r = divmod a b` и
  `q, r = take 2 primes n`.
- Старые однострочные `function sum` и `function A unknown mul` остаются.

Пример с временными:

```text
function squareSum
  in a: natural
  in b: natural
  out result: natural
  body
    s = sum a b
    result = mul s s
end
```

## Выходы и потоки

- `out x: T` — ровно один результат.
- Несколько `out` — фиксированный кортеж.
- `out x: T...` — поток (0+), например `primes`.
- `out x: T?` и `out x: T+` — возможное расширение (0/1 и 1+).
- Несколько потоков в плоском результате не поддерживаются: непонятно, где
  граница. Для этого нужны структурные значения (см. 0017).

Комбинаторы над потоком (специальные формы, не обычные функции):

- `take n expr` — ровно `n` первых результатов, иначе ошибка;
- `drop n expr` — остаток после первых `n`;
- `first expr`, `rest expr`, `count expr`;
- `sort expr` — если тип имеет порядок;
- `shuffle expr` — случайная перестановка (нестабильна).

`primes[2]` — это не `take`, а индексация (`at`). `take` — срез/начало
последовательности.

## Перегрузки и `use`

Одно имя может иметь несколько типизированных вариантов:

```text
sum: natural × natural -> natural
sum: integer × integer -> integer
```

Правила:

- точное совпадение лучше расширения (`natural -> integer`);
- если подходят два варианта и нет более точного — ошибка;
- перегрузка только по типу результата запрещена;
- у перегрузок пользовательской функции должна быть одинаковая арность.

В теле можно ссылаться на конкретную перегрузку:

```text
use sumNat = sum natural natural -> natural
use sumInt = sum integer integer -> integer
```

или явно: `sum[natural,natural] a b`. `use` действует в пределах блока.

## Типы

Внутри тела разрешено только расширение:

```text
natural -> integer -> rational -> real -> complex
integer -> gaussian -> complex
```

Сужение — явное (`to natural b`) или проверяемое на границе `out`
(`out r: natural`, тело `mod a b`). Ошибка сужения не должна ронять игру:
см. 0019.

Литералы:

- `sign = -1` — bare-литерал по умолчанию `integer`; при выходе `integer` тип
  совпадает, при выходе `natural` значение проверяется и расширяется/сужается
  на границе;
- `t = integer=-1` — явный типизированный литерал;
- чтобы вызвать natural-перегрузку с константой, пишите `natural=2`;
- `real=1.5`, `gaussian=2+3i` — на будущее;
- `rational=3/4`, `complex=1.5-2i` — если появится числовая башня (0023).

Полная числовая башня, преобразования и точность описаны в 0023; паритет
встроенных функций для новых типов — в 0024.

Вывод типа литерала из объявленного выхода пока не делается: bare-литерал
считается `integer`, а приведение к `natural` происходит при присваивании
выходу. Это сохраняет строгую проверку отрицательных значений, но требует
явного `natural=...` там, где важна именно natural-перегрузка.

## Случайность

`rand` — единственная простейшая случайная функция. `sumr`, `mulr` и т.п.
можно определить как пользовательские:

```text
function sumr
  in a: integer
  in b: integer
  out result: integer
  body
    base = sum a b
    noise = rand -10 10
    result = sum base noise
end
```

- стабильность вычисляется транзитивно;
- `Solver` уже вызывает `outcomes()` для нестабильных функций;
- исходы — декартово произведение случайных связываний, с лимитом;
- случайное связывание сэмплируется один раз на исход; два `rand` —
  независимые сэмплы.

## `if`

`if` — специальная форма с ленивыми ветками, а не строгая функция.
Обе ветки должны иметь совместимый результат. Условие — `bool` или 0/1.
Арифметический выбор `c*a + (1-c)*b` годится только для чисел и не ленив.

## Компиляция

- текущая версия: проверка структуры при загрузке + интерпретация тела;
- разрешение имён, перегрузок и алиасов — во время вычисления;
- ошибки типов/домена не роняют игру и содержат имя функции и строку `body`;
- обнаружение циклов — ограничение глубины вызовов; рекурсия пока не
  запрещена статически;
- `stable` и спецификация результатов вычисляются при загрузке;
- следующий этап: AST, статическая проверка типов, точная локализация ошибок.

## Чего не хватает из Java

В Java у каждой `Function` есть `remainingUses`:

- вызов `use(isInfinityFunctions, args)` проверяет счётчик;
- после успешного `compute` счётчик уменьшается на 1;
- при `infinityFunctions = true` счётчик не меняется;
- ошибка `compute` не должна расходовать использование;
- `calc` всегда вызывает функции с `infinityFunctions = true`.

В C++ у `Fn` нет счётчика, поэтому лимит вызовов выразить нельзя. Это меняет
не только интерфейс, но и состояние решателя: счётчики нужно добавить в ключ
состояния и копировать вместе с историей. Подробный синтаксис `uses` и
семантика — в 0020.

Java-реестр хранит простейшие функции с учётом типов, а C++ уже поддерживает
перегрузки пользовательских функций. Но лимит использований не зависит от
перегрузки: счётчик нужен на функцию/перегрузку. Типы и числовая башня — 0023,
недостающие встроенные функции — 0024.
