# func(math)

[![CI](https://github.com/Lexonixeo/funcmath-opencode/actions/workflows/ci.yml/badge.svg)](https://github.com/Lexonixeo/funcmath-opencode/actions/workflows/ci.yml)

Игра-головоломка про числа и функции. Полное руководство игрока — в
[`docs/gameplay.md`](docs/gameplay.md). В релизных архивах рядом лежат
`README.txt` и `.txt`-версии документации для чтения без Markdown.

## Смысл игры

У вас есть **набор чисел** и **набор функций**. У функции есть арность: она
забирает несколько чисел и возвращает одно или несколько. Применив функцию, вы
**убираете её аргументы из набора и кладёте на их место результаты**. Цель —
получить в наборе заданное число. Набор при этом обычно «сжимается», поэтому
важен порядок операций: это головоломка на планирование последовательности.

Пример: набор `1 1`, функция `sum`, цель `2`. Вводим `sum 1 1` → оба числа
исчезают, в набор добавляется `2` — уровень пройден.

Особые механики:

- **Типы значений.** Числа бывают `natural` (неотрицательные) и `integer`
  (знаковые). В старых уровнях все числа `integer`; новые уровни могут
  использовать `natural`.
- **Неизвестные функции.** Некоторые функции названы просто `A`, `B`, `C` — их
  поведение скрыто, и его нужно выяснить экспериментально (командой `calc`,
  которая считает, но не меняет набор).
- **Случайность.** `rand` возвращает случайное число, `sumr` — сумму с
  небольшим разбросом; решатель перебирает допустимые исходы. Полноценная
  модель погрешности измерений пока остаётся идеей: сейчас цель проверяется
  точно.
- **Откат и история.** `back` возвращает набор к состоянию до последнего хода,
  `reset` — к началу уровня, `history` показывает сделанные ходы. После каждого
  хода печатается текущий набор.
- **Пользовательские функции.** Функцию можно собрать из простейших блоком
  `function … in … out … body … end` прямо в уровне или сохранить в
  `data/functions/*.fn`. Поддерживаются именованные параметры/выходы,
  временные переменные, потоки результатов, перегрузки и случайность.
- **Имена чисел.** Число в наборе может иметь метку (`number natural 3 as x`);
  её можно вводить вместо значения.

Выражения можно писать в привычной инфиксной форме: `1 + 2`,
`(1 + 2) * 3`, `sum(1, 2) + 3`. Старая префиксная запись `func a b` тоже
работает; аргументы могут быть вложенными: `sum 1 sum 2 3`. Некоторые функции
унарные или возвращают несколько результатов — например, `primes 30` даёт
`2 3 5`.

Игра также помогает осваивать тему №19 ЕГЭ (теория чисел): остатки, делимость,
НОД/НОК, разложение на множители. Идеи развития в этом направлении — в
[`docs/ideas/`](docs/ideas/).

## Быстрый старт

Сборка через g++ из корня репозитория:

```sh
g++ -std=c++17 -Wall -Wextra -O2 -o funcmath \
    src/Helper.cpp src/Functions.cpp src/Expression.cpp src/Function.cpp \
    src/LevelStore.cpp src/Level.cpp src/Solver.cpp src/LevelGenerator.cpp \
    src/Player.cpp src/Game.cpp src/main.cpp
./funcmath
```

Или CMake:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

В Windows удобно `build.bat`. Запускать игру нужно из корня репозитория
(рядом с `data/`) или из каталога сборки, куда CMake копирует `data/`.

### Требования

Для сборки:

- компилятор C++17;
- CMake 3.16+ (рекомендуется более новый);
- терминал с поддержкой UTF-8.

Для готовых релизов:

- Windows 10/11 x64;
- Linux x64 с glibc 2.35+ (например, Ubuntu 22.04+);
- macOS 12+ arm64;
- папка `data/` рядом с исполняемым файлом.

Готовые сборки не требуют установленного компилятора или интернета.

## Режимы командной строки

```sh
funcmath --check    # проверить все уровни на решаемость
funcmath --author   # создать новый уровень
funcmath --function # редактор пользовательской функции
```

Подробности о командах, формате `.lvl` и функциях — в
[`docs/game.md`](docs/game.md).

## Тесты и CI

На GitHub Actions при каждом push в `main` и каждом pull request собираются
Windows/MSVC, Linux/GCC и macOS/AppleClang, затем запускается `ctest`.

Локально:

```sh
ctest --test-dir build -C Release --output-on-failure
```

`ctest` проверяет парсер инфиксной записи и решаемость всех уровней. Для
уровня 18 используется увеличенный лимит решателя: он находится, но требует
более глубокого поиска.

## Релизы

Релиз создаётся по тегу `v*`:

```sh
git tag v0.2.0
git push origin v0.2.0
```

Workflow соберёт архивы и прикрепит их к GitHub Release:

```text
funcmath-ds-v0.2.0-windows-x64.zip
funcmath-ds-v0.2.0-linux-x64.tar.gz
funcmath-ds-v0.2.0-macos-arm64.tar.gz
SHA256SUMS.txt
```

Ручной запуск `Release` через `workflow_dispatch` собирает те же артефакты, но
не публикует релиз. Внутри архива лежат исполняемый файл, `data/`, README и
документация. Для релиза дополнительно создаются `README.txt` и
текстовые версии основных документов `docs/*.txt`.
