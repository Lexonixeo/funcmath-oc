# 0009. Векторы и другие объекты вместо только чисел

**Статус:** идея
**Сложность:** высокая

## Суть

Сейчас объект — это `long long`. Письмо руководителю предлагает расширить игру:
не только скаляры, но и векторы, матрицы, строки, предметы из Minecraft и модов.
Это качественно меняет движок: появляется **типизированное значение**.

Числовая башня (`rational`, `real`, `complex`, `gaussian`) — отдельный проект
0023. Здесь речь о нечисловых значениях; смешивать оба расширения в одном
изменении не стоит.

```cpp
struct Value {
    enum class Type { Scalar, Vec2, Vec3, String, Item };
    Type type;
    long long scalar;          // для Scalar
    std::vector<long long> vec; // для Vec2/Vec3
    std::string str;           // для String
    std::string itemId;        // для Item
    int count = 1;             // для Item
};
```

Функции тоже становятся типизированными: `sum` принимает два скаляра,
`vadd` — два вектора, `dot` — два вектора и возвращает скаляр, `craft` —
два предмета и возвращает предмет.

## Что можно добавить

### Векторы

- `vadd(a, b)`, `vsub(a, b)`, `vscale(a, k)` (но нужен третий аргумент или
  отдельная функция с числом), `dot(a, b)`, `cross(a, b)`, `norm(a)`, `vlen(a)`.
- Уровни: «получи вектор (3, 4)», «получи скаляр 25 через `dot`», «собери
  единичный вектор».

### Строки

- `concat`, `reverse`, `substr`, `length`, `replace`.
- Уровни на преобразование строк; полезно для будущего UI и редактора.

### Предметы (Minecraft и моды)

- Предмет — идентификатор + количество.
- Функция — рецепт: `craft(бревно, бревно) = доски`, `craft(доски, палка) = ...`.
- Рецепты в Minecraft часто 3×3, а функция бинарная. Варианты:
  - начать с бинарных рецептов («2 предмета → 1 предмет»);
  - добавить функции с N аргументами (тогда меняется формат уровня и парсер);
  - крафт-стол как отдельный экран, а не функция.
- Уровни: «собери алмазную кирку из доступных предметов», «получи 4 доски».

## Что придётся изменить в движке

- `Num` → `Value`; арифметика, сравнение, хэширование, сортировка.
- Формат `.lvl`: тип объектов, типы аргументов функций, возможно N аргументов.
- Решатель: состояние — мультимножество `Value`; нужны канонический ключ и
  ограничение доменов (векторы из целых в диапазоне, конечный инвентарь).
- Подсказки и `--check`: проверка типов и достижимости.
- UI: иконки, тултипы, drag-and-drop.

## Поэтапный план

1. Ввести `Value` и оставить только `Scalar` — убедиться, что старые 62 уровня
   и решатель работают без изменений.
2. Добавить `Vec2` и 3–5 векторных функций, 5 уровней.
3. Добавить строки.
4. Добавить предметы и бинарные рецепты; позже — N-арные функции.
5. Только после этого — большие наборы предметов/модов.

## Зачем

- Это прямое развитие идеи игры: «объекты» вместо «чисел».
- Векторы и строки дают новые типы мышления, не ломая ядро.
- Предметы делают игру ближе и понятнее широкой аудитории.
- Поэтапный путь позволяет сохранить работающую числовую версию.

`src/Functions.{h,cpp}`, `src/Function.{h,cpp}`, `src/LevelStore.*`,

## Риски

- Сильно усложняется решатель: векторы и предметы увеличивают пространство
  состояний.
- N-арные функции ломают текущий формат «функция = два аргумента».
- Нужна аккуратная типизация, иначе ошибки будут ловиться только в рантайме.
- Не стоит смешивать все типы в одном уровне без необходимости.
