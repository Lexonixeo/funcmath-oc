# 0007. Типизированные значения natural/integer

**Дата:** 2026-10-20

## Что сделано

- Добавлен `src/Value.h` — типизированное значение, аналог `MathObject` из
  Java-прототипа. Внутри `std::variant<Natural, Integer>`; тип хранится у
  каждого числа, а не у уровня.
- `natural` — строгий неотрицательный тип: отрицательные значения нельзя
  загрузить, а `sub`/`neg2` и подобные операции с отрицательным результатом
  выбрасывают ошибку. `integer` — обычный знаковый 64-битный тип.
- Все значения в игре (`numbers`, `answer`, решатель, история, решатель
  случайности) переведены с `long long` на `Value`.
- Формат `.lvl` расширен:
  - `number natural 3`, `number integer -5` — по одному числу;
  - `answer natural 12` / `answer 12`;
  - старый `numbers 1 2 3` остаётся и означает `integer`.
- `--author` спрашивает тип чисел (`integer` по умолчанию) и проверяет
  отрицательные значения для `natural`.
- В заголовке natural-уровня показывается тип чисел; в смешанном наборе тип
  печатается рядом с числом.
- Старые 62 уровня не переписаны: все их числа и ответы загружаются как
  `integer`, поведение сохраняется.

## Зачем

Это фундамент для функций с произвольным числом аргументов и результатов, а
затем для `rational/real/complex`. Тип на уровне был бы слишком грубым: в
прототипе тип есть у каждого `MathObject`, и смешанные наборы — часть
механики.

## Проверка

- Сборка `g++ -std=c++17 -Wall -Wextra -O2` без ошибок.
- `--check` по старым 62 уровням: **решаемо 61, не найдено 1, со случайностью 7,
  с ошибками 0** — как до изменений (уровень 18 по-прежнему не находится DFS
  за стандартный лимит).
- Временный natural-уровень `sub 5 2 = 3` решается; `sub 2 5` даёт ошибку
  «нельзя вычесть большее из меньшего» и не портит набор.
