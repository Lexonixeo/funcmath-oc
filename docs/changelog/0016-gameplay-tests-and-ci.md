# 0016. Руководство игрока, тесты и CI/релизы

**Дата:** 2026-10-22

## Что сделано

- Добавлено полное руководство игрока `docs/gameplay.md`: типы чисел, имена,
  префиксная и инфиксная запись, команды, функции, потоки, случайность и
  разбор типичных ошибок.
- Стартовая справка внутри уровня сокращена до нескольких строк; подробности
  вынесены в руководство.
- Добавлен `docs/level-design.md` с принципами создания уровней: одна новая
  идея на уровень, туториал в начале, учебный порядок тем, дозированные
  обманки, проверка через `--check` и борьба с клонами. Уточнено, что типы не
  вводятся в туториале раньше времени, комбинации можно давать сразу после
  освоения нужных тем, а пасхальные числа школ — фон, а не обязательная
  подсказка.
- Добавлена идея `docs/ideas/0026-physical-quantities-and-tolerance.md`:
  физические величины с погрешностью, распространение ошибки и проверка
  ответа в допуске. Текущая случайность — ранний прототип этой идеи.
- Добавлены `AGENTS.md` и `docs/ai-context.md`: краткая инструкция для
  ИИ-агента и подробная карта состояния, решений, известных проблем и
  дорожной карты.
- Добавлены регрессионные тесты:
  - `tests/expression_tests.cpp` проверяет нормализацию инфикса, приоритеты,
    вызовы, унарный минус и ошибки;
  - CTest запускает по одному тесту на каждый уровень, кроме временно
    исключённого уровня 18.
- В CMake добавлены `BUILD_TESTING`, тестовый executable, автоматический
  список уровней и упаковка CPack.
- Добавлены GitHub Actions:
  - `ci.yml` — сборка и тесты на Windows/MSVC, Linux/GCC и macOS/AppleClang;
  - `release.yml` — сборка архивов по тегу `v*`, ручной запуск без публикации,
    проверка версии, `SHA256SUMS.txt` и прикрепление файлов к GitHub Release.
- README дополнен требованиями, командами тестов, схемой релизов и ссылками
  на новую документацию; добавлен CI-бейдж.
- Артефакты релиза называются
  `funcmath-ds-vX.Y.Z-<os>-<arch>`; версия задаётся тегом.

## Зачем

Игроку нужен один подробный источник правды, а не длинная портянка при каждом
старте уровня. Разработчику и ИИ-агенту нужен явный контекст, чтобы не
восстанавливать историю решений заново. CI должен ловить поломки парсера и
уровней на трёх платформах, а релиз — собираться воспроизводимо по тегу, а не
вручную с локальной машины.

## Проверки

- `cmake -S . -B build -DCMAKE_BUILD_TYPE=Release` — конфигурация.
- `cmake --build build --config Release --parallel` — сборка MSVC.
- `ctest --test-dir build -C Release --output-on-failure` — 85 тестов,
  все прошли.
- `cmake --build build --target package --config Release` — собран
  `funcmath-ds-v0.2.0-windows-x64.zip`; внутри бинарник, runtime DLL, `data/`,
  README и документация, без пользовательских сохранений.
- Уровень 18 временно исключён из CTest через
  `FM_KNOWN_UNSOLVABLE_LEVELS`; после аудита его нужно вернуть.
