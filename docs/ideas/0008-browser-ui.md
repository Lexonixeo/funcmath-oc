# 0008. Браузерный интерфейс в духе nandgame

**Статус:** идея
**Сложность:** высокая

## Суть

Сделать игру не только консольной, но и браузерной: карта уровней, перетаскивание
функций на числа, наглядные связи, анимации, подсказки. Вдохновение — nandgame:
там сложные идеи подаются через простые визуальные шаги.

## Варианты архитектуры

### A. C++ → WebAssembly (рекомендуется для одиночной игры)

- Ядро (`Functions`, `Level`, `Solver`, `LevelStore`) компилируется в WASM через
  Emscripten.
- UI на TypeScript/JS вызывает экспортированные функции: загрузить уровень,
  применить функцию, получить подсказку.
- Плюсы: один движок для консоли и браузера, нет сервера, офлайн-игра.
- Минусы: сборка WASM, работа с файлами уровней (упаковать в виртуальную ФС или
  загружать JSON).

### B. Сервер на C++ + браузерный клиент

- C++-сервер (HTTP/WebSocket) хранит уровни, аккаунты, проверяет ходы.
- Плюсы: авторитетный сервер, проще мультиплеер и античит.
- Минусы: хостинг, задержки, больше инфраструктуры.

### C. Переписать логику на TypeScript

- Плюсы: самый простой UI и быстрая разработка.
- Минусы: два движка, риск расхождений; плохо для мультиплеера с C++.

**План:** начать с A, а для мультиплеера (идея 0011) при необходимости добавить
серверную часть.

## UI: минимальный MVP

- Экран уровня: набор чисел, список функций, цель.
- Две выбранные карточки чисел + функция → предпросмотр результата → «применить».
- Undo/redo, reset, история (в будущем — дерево, идея 0001).
- Подсказка: подсветить пару и функцию.
- Карта уровней с прогрессом.
- Адаптивность под телефон.

## UI: вторая итерация

- Анимация «два числа исчезают, результат появляется».
- Drag-and-drop функций на пары.
- Тёмная/светлая тема, настройки звука.
- Объяснения функций по клику (теория).
- Красивые иконки для функций и будущих объектов (векторы, предметы).

## Технологии

- Vite + TypeScript; React/Svelte — по вкусу, можно и без фреймворка.
- SVG/Canvas для анимаций, CSS для карточек.
- Emscripten-сборка ядра; данные уровней — JSON, сгенерированный из `.lvl`.
- Сохранение прогресса — `localStorage` (одиночная игра) или сервер.

## Зачем

- Порог входа ниже: не нужно ставить компилятор и запускать консоль.
- Визуализация делает механику «два числа → результат» понятной сразу.
- Браузер — естественная база для мультиплеера и редактора уровней.
- Консоль остаётся быстрым полигоном для движка и решателя.

## Что затронет

Новые каталоги `web/` (UI) и, возможно, `src/wasm/` (экспорт API);
`CMakeLists.txt` (Emscripten-цель), `docs/`, `README.md`.
Ядро придётся отделить от консольного ввода-вывода: `Level` сейчас печатает
напрямую в `std::cout`, понадобится слой событий/результатов.

## Риски

- Много работы: UI, сборка WASM, адаптация ввода-вывода.
- Нельзя потерять консольную версию и её тесты.
- Не увлекаться анимациями в ущерб геймплею.
