# 0005. Прогресс, достижения и сохранение партии

**Статус:** идея
**Сложность:** низкая

## Суть

Несколько небольших улучшений вокруг прогресса:

- **Сохранение партии.** Сейчас при выходе из уровня набор чисел теряется.
  Можно сохранять текущий уровень, набор и историю/дерево ходов в файл игрока
  и продолжать с того же места.
- **Статистика по уровням.** Для каждого уровня хранить: попытки, лучшее число
  ходов, использованные подсказки, время.
- **Достижения.** Например: «пройти уровень без подсказок», «пройти за N ходов»,
  «пройти все уровни с `mod`», «решить случайный уровень с первого раза».
- **Экспорт решения.** Команда `replay` печатает пройденный путь в виде
  списка ходов — удобно делиться и вставлять в отчёты.
- **Карта уровней.** Команда `map` показывает уровни и отметки о прохождении.
- **Цветной вывод.** На Windows 10+ можно включить ANSI-цвета: цель — одним
  цветом, ошибки — другим, успех — третьим (с флагом `--no-color`).

## Уточнение после сверки с Java

В Java сохранение игрока — это не только список пройденных номеров. `Player`
хранит:

- `lastLevel` — состояние последнего уровня (не просто номер);
- `completedLevels` — множество ключей `(PlayFlag, ID)`;
- `levelStates` — незавершённые состояния по ключам;
- `levelStatistics` — статистику по ключам;
- `playerVersion` — версию формата сохранения.

`DLStats` для уровня хранит `startTime`, `endTime`, `functionUses` и
`completed`; при слиянии двух прохождений берётся лучший результат по времени
и числу вызовов функций. `PlayerUpdater` умеет обновлять старые сохранения по
графу версий, а не только «если поля нет — считать пустым».

Отсюда конкретные требования к C++:

- сохранять не только `completed`, но и состояние/статистику текущего уровня;
- различать `DEFAULT` и `CUSTOM` по ключу, а не по одному числу (0022);
- при нескольких целях (0021) и лимитах функций (0020) статистика должна
  учитывать число целей/вызовов;
- для `lastLevel` хранить категорию, номер и снимок набора;
- предусмотреть версию формата и миграцию.

Это не отменяет поэтапность: можно начать с сохранения текущего уровня, затем
добавить статистику и только потом достижения.

## Зачем

- Меньше раздражения: случайный выход не обнуляет партию.
- Прогресс и достижения мотивируют проходить больше уровней.
- `replay` помогает разбирать свои решения и решения других.
- Цвета и карта делают консольный интерфейс понятнее.

## Эскиз реализации

- Расширить формат файла игрока: добавить секцию `current_level`,
  `current_numbers`, `history/tree`, `level_stats`.
- Аккуратно мигрировать старые файлы (если секций нет — считать пустыми).
- Достижения проверять после успешного прохождения уровня.
- `map` — простая таблица `уровень | пройден | лучший результат`.
- Цвета — небольшие функции-обёртки, отключаемые переменной окружения
  `NO_COLOR` или флагом.

## Что затронет

`Player.{h,cpp}`, `Game.cpp`, `Level.{h,cpp}` (сохранение состояния),
`main.cpp`, `README.md`.

## Риски

- Совместимость сохранений: старые файлы не должны ломаться.
- Не стоит усложнять формат раньше времени; можно начать только с сохранения
  текущего уровня и статистики.
