# 0003. Кратчайшее решение для `hint` и `--check`

**Статус:** идея
**Сложность:** средне-высокая

## Суть

Сейчас решатель — обычный DFS с лимитом узлов и времени. Он находит **какое-то**
решение, но не обязательно кратчайшее. Из-за этого:

- `hint` может предлагать длинный путь, хотя рядом есть короткий;
- уровень 18 не находится за стандартный лимит, хотя решение из 9 ходов есть;
- `--check` не умеет отличать «сложный» уровень от «тривиального».

Предлагается искать **кратчайшее** решение (или хотя бы более короткое):

1. **BFS / IDDFS** по числу ходов.
2. **Канонизация состояния**: набор чисел — это мультимножество, поэтому
   сортируем его и храним в `unordered_set`. Два разных порядка ходов,
   приводящие к одному набору, эквивалентны (для детерминированных функций).
3. **Transposition table** и для DFS: не заходить в уже посещённое состояние.
4. **Упорядочивание ходов**: сначала пробовать пары, которые могут дать цель
   (`a + b == T`, `a * b == T`, `abs(a - b) == T`), затем остальные.
5. Для `hint` показывать первый ход кратчайшего пути и длину пути.
6. Для `--check` выводить `min ходов` и, по желанию, число найденных решений
   (с ограничением).

## Зачем

- Подсказки становятся полезнее и короче.
- Уровень 18 перестаёт быть «исключением».
- Появляется объективная метрика сложности: минимальное число ходов.
- Можно автоматически предупреждать автора уровня о тривиальном решении
  (1–2 хода).

## Эскиз реализации

```cpp
struct State {
    std::vector<Num> nums;  // отсортированы
    bool operator==(const State& other) const;
};

struct StateHash {
    std::size_t operator()(const State& s) const;
};
```

- BFS хранит `State -> (parent, move)`, чтобы восстановить путь.
- Ограничения: максимум состояний (например, 2–5 млн), максимальная глубина,
  таймаут. При превышении — откат к текущему DFS.
- Для случайных функций переход размножается по `fmath::outcomes`.
- В `--check` добавить колонку `min ходов`, в `hint` — `(кратчайший путь: N)`.

## Риски

- BFS может съесть память на уровнях с большим ветвлением (18, 26).
- Нужен аккуратный fallback на DFS и честное сообщение «поиск прерван».
- Для случайных функций «кратчайший» означает «кратчайший при удачном исходе»;
  это стоит явно писать в подсказке.
