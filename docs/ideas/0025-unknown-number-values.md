# 0025. Неизвестные числа и режим угадывания

**Статус:** экспериментальная идея
**Сложность:** высокая

## Что было в Java

В истории Java-прототипа был класс `FUnknown` — число с секретом:

```java
class FUnknown extends FInteger {
    String unknownName;
    FInteger number;   // настоящее значение, скрытое от игрока
    boolean isKnown;
    boolean isFound;
}
```

Идея:

- игрок видит имя (`x`, `y`, ...), а не значение;
- операции над неизвестным числом используют скрытое значение и возвращают
  новый `FUnknown`, но историческая реализация создавала его с
  `isKnown = true`, то есть результат часто сразу печатался как число;
- `toString` показывает имя, пока число не найдено;
- после находки имя получает префикс `FOUND_`;
- специальная функция `equal a b c` возвращает `c`, если `a` и `b` равны, и
  пустой поток иначе — так можно было строить проверки без `if`;
- уровень с `resultClassName == "unknown"` работал в особом режиме: `calc` и
  `back` отключались, а ходы шли через отдельную ветку вычисления.

`FUnknown` был добавлен в нескольких коммитах, затем развитие остановлено.
В текущем `DefaultPack` он даже не регистрируется: файл остался как
исторический артефакт. В C++ такого типа нет.

## Зачем это было нужно

Из сообщения автора видны две задачи:

1. **Угадывание чисел.** Интерактивные задачи в духе олимпиадного
   программирования: дано неизвестное число, его нужно определить
   экспериментами.
2. **Микрокалькулятор МК-17.** В памяти одно число `x`; доступны только
   проверка равенства, сложение и поиск корней квадратного уравнения.
   Нужно узнать, равно ли `x` единице.

Это не то же самое, что «получить число из набора». Здесь само значение —
секрет, а цель — не числовой ответ, а **факт** (`x` найдено/равно 1).

## Почему разработка остановилась

- Не было ясно, как отделить «неизвестное» от обычного числа в решателе:
  скрытое значение нельзя перебирать как обычное состояние.
- `calc` и `back` в таком режиме ломают идею эксперимента.
- Операции над `FUnknown` не имели продуманной модели раскрытия: арифметика
  создавала уже «известный» результат и тем самым обходила секрет.
- `equal` с пустым потоком — хрупкая замена условию.
- В итоге класс стал мёртвым кодом: его не регистрируют, а уровни 43/44 из
  той эпохи остались историей.

## Не путать с другими механиками

| Механика | Что скрыто | Что видит игрок | Решатель |
|----------|------------|-----------------|----------|
| Имена-метки (0017) | ничего | имя как псевдоним значения | видит значение |
| Неизвестные функции (`A unknown mul`) | поведение функции | имя и арность | перебирает поведение |
| `FUnknown` (эта заметка) | само значение числа | имя, пока не найдено | не может перебирать секрет обычным DFS |

Имена-метки — это удобство ввода/вывода. `FUnknown` — другая механика уровня,
и её нельзя реализовать просто как ещё один вариант `Value` без отдельного
режима.

## Если возрождать: предлагаемая модель

### Отдельный режим уровня

Не добавлять `Unknown` в общий `Value` и не включать его в обычные уровни.
Нужен явный флаг/категория:

```text
rule unknownNumbers true
```

или отдельный `LevelKind::Guess` (0022). Тогда:

- `calc` и `back` можно запретить правилами 0020;
- обычный решатель не пытается угадать секрет;
- `--check` либо не поддерживает такие уровни, либо перебирает конечный
  домен секретов отдельным алгоритмом.

### Синтаксис

Точный формат нужно выбрать; возможный эскиз:

```text
number unknown x = 5
number unknown y = -2

# цель — найти x, а не получить число 5
answer found x
```

Здесь `5` и `-2` — авторские секреты, которые не показываются игроку. При
экспорте уровня их придётся либо оставлять в файле (игрок может подсмотреть),
либо хранить отдельно на сервере. Для локальной игры это приемлемо, как и
пароли в сохранениях; для мультиплеера — нет.

Альтернатива: `number unknown x range 0 100` — тогда секрет выбирается при
старте, а не хранится в уровне. Это ближе к генерации, но усложняет
`--check` и воспроизводимость.

### Раскрытие

Нужно решить, что именно считается находкой:

- `found x` — игрок доказал значение (например, через `equal x 1`);
- `reveal x` — явная команда, которая показывает значение (слишком просто);
- `equal a b c` — исторический вариант: вернуть `c` при равенстве, иначе
  пустой поток;
- `is x 1` — булева проверка, но `bool`/`if` пока не реализованы (0015).

Операции над неизвестным должны либо сохранять секрет, либо явно его
раскрывать. Нельзя, чтобы `sum x 0` внезапно печатал значение.

### Цель

Цель — не мультимножество чисел, а предикат:

```text
goal found x
goal equal x 1
```

Это ещё один аргумент в пользу того, что `FUnknown` — отдельный тип уровня, а
не расширение `answer` из 0021.

## Влияние на решатель и проверки

- Обычный `Solver` ищет числа в наборе; секрет не является числом набора.
- Если домен секрета конечен и мал, можно перебрать все значения и проверить,
  что авторское решение работает; это отдельный режим `--check`.
- Если домен бесконечен, автоматическая проверка нерешаема; нужен авторский
  путь и ручная проверка.
- `hint` должен выдавать эксперимент, а не значение секрета.
- Ошибки не должны печатать скрытое значение в тексте (0019).

## Что затронет

- `src/LevelStore.*` — новый тип числа/цели, секреты;
- `src/Value.h` — возможно, отдельный `SecretValue`, но не общий `Value`;
- `src/Level.*` — режим угадывания, `equal`/`found`, запрет `calc`/`back`;
- `src/Functions.*` — `equal` и другие операции над секретом;
- `src/Solver.*` — отказ или отдельный перебор;
- `src/main.cpp` — `--check` для режима;
- `docs/game.md`, `docs/level-authoring.md`;
- будущий UI/мультиплеер — сокрытие секрета.

## Риски

- Игрок подсмотрит секрет в `.lvl` или сохранении; для честной игры нужен
  сервер или генерация секрета.
- `FUnknown` легко превращается в «магическую» функцию, которая ломает
  обычные типы и решатель.
- Без `if`/`bool` проверка равенства через пустой поток неудобна и плохо
  диагностируется.
- Скрытые значения конфликтуют с `--check`, кэшем решателя и обменом уровнями.
- Механика может оказаться интересной только в нескольких уровнях; сначала
  стоит сделать один прототип вне основного движка.

## Рекомендация

Не реализовывать в ближайшем цикле. Если возвращаться — только как отдельный
экспериментальный режим уровня, после 0021 (цели), 0020 (правила) и, желательно,
после появления `if`/`bool`. Обычные имена-метки (0017) и неизвестные функции
уже покрывают большинство бытовых задач; `FUnknown` — это другая игра.
