# 0021. Несколько целей и метаданные уровня

**Статус:** идея
**Сложность:** средняя

## Что есть в Java, но нет в C++

В Java у уровня `DLInfo` есть:

- `ArrayList<MathObject> ans` — не одно число, а список целей;
- `String name` — авторское название уровня;
- `ArrayList<String> hints` — последовательность подсказок;
- `PlayFlag` и `ID` — категория и номер уровня.

Проверка прохождения в `DefaultLevel.numsCheck` устроена как проверка
**подмножества с кратностями**:

```java
for (MathObject arg : args) {
    if (nums.contains(arg)) nums.remove(arg);
    else return false;
}
return true;
```

То есть текущий набор должен содержать все цели, но может содержать и лишние
числа. Порядок целей не важен, а две одинаковые цели требуют двух экземпляров.
`equals` у числовых объектов учитывает тип, поэтому `natural 2` и `integer 2` —
разные цели.

В C++ `LevelData.answer` — одно значение, а `Solver::solve` принимает один
`Num target`. Метаданных `name`/`description` в формате `.lvl` тоже нет:
`LevelData.title` заполняется кодом как «Уровень N.».

Подсказки в Java — это именно список: команда `hint` сначала показывает первую,
потом вторую и так далее. Формат хранения и показ подсказок разобраны отдельно
в 0013; здесь важно только, что `name`, `description` и `hints` — части одного
заголовка уровня.

## Предлагаемый формат

Минимальное расширение, совместимое со старыми уровнями:

```text
name Собери пару
description Получи 12 и 7; порядок целей не важен.
answer natural 12
answer integer 7
```

- `name` — короткое название для заголовка и списка уровней;
- `description` — одна строка с пояснением; длинные тексты лучше хранить в
  sidecar-файлах, как в 0013;
- повторяющийся `answer` добавляет ещё одну цель. Старый уровень с одним
  `answer` читается без изменений.

Дубликаты целей задаются повторением строки:

```text
answer natural 2
answer natural 2
```

Это значит «нужны два экземпляра `natural 2`», а не «цель 4».

Альтернатива — блок `answers` с несколькими строками. Она удобнее для
сериализации, но требует нового ключа и хуже читается в коротких уровнях.
Повторяющийся `answer` лучше ложится на текущий построчный парсер.

`title` пока лучше не убирать: это служебная строка «Уровень N.» для старых
экранов. `name` — отдельное авторское название, которое может быть пустым.
Категория и номер уровня (`PlayFlag`, `ID`) описаны в 0022; здесь они не
меняются.

## Семантика целей

1. **Тип входит в цель.** `answer natural 2` не принимает `integer 2`.
2. **Кратность входит в цель.** Две строки `answer ... 2` требуют двух копий.
3. **Лишние числа разрешены.** Уровень завершён, если в наборе есть все цели;
   набор не обязан совпадать с целями.
4. **Порядок не важен.** `answer 12`, `answer 7` и наоборот — одно и то же.
5. **Стартовый набор может уже удовлетворять цели.** Это допустимо для
   калькуляторов и песочниц, но `--validate` должен предупреждать: уровень
   проходится без ходов.
6. **Стримы не меняют правило.** Если ход вернул несколько результатов, все
   они попадают в набор, после чего проверяются цели.

Именно подмножество, а не точное равенство, позволяет делать уровни вида
«получи 12 и 7, остальное не важно» и не заставляет игрока тратить все числа.

## Решатель

Сигнатуру стоит заменить на список целей:

```cpp
bool solve(const std::vector<Num>& numbers,
           const std::vector<Fn>& functions,
           const std::vector<Num>& targets,
           std::vector<Move>& moves, ...);
```

Проверка цели — та же операция «содержит все элементы с кратностями», что и в
`Level`. Для небольших списков её можно делать линейно; для больших — считать
отсортированный вектор целей и сравнивать с ним.

Что меняется в DFS:

- начальное состояние проверяется сразу: цель может быть уже достигнута;
- эвристика `missingCount` считает, сколько целей ещё не покрыто, и поощряет
  ходы, уменьшающие это число;
- `hint` возвращает первый ход полного плана, а не план только до одной цели;
- `--check` печатает число целей и, при желании, сколько осталось;
- при нескольких целях полезно ограничить перебор состояниями, где количество
  чисел не растёт бесконечно (например, отсекать бесполезные `sumr`).

Стратегия перебора остаётся заменяемой: меняется предикат цели и эвристика, а
не сам DFS. Это важно, чтобы позже можно было подключить BFS/IDDFS из 0003.

## Метаданные и отображение

- Заголовок уровня: `name`, при отсутствии — `title`.
- Перед уровнем можно показать `description`.
- Цели печатаются списком: `12(natural), 7(integer)`.
- Если цель одна, старый вывод сохраняется.
- `hint` не должен случайно раскрывать все цели сразу: подсказка — это ход, а не
  полный ответ.

## Что затронет

- `src/LevelStore.h` — `std::vector<Num> answers`, `name`, `description`;
- `src/LevelStore.cpp` — разбор повторяющегося `answer`, запись, обратная
  совместимость;
- `src/Level.cpp` — проверка подмножества и вывод целей;
- `src/Solver.*` — список целей и эвристика;
- `src/main.cpp` — `--check` и отчёты;
- `src/LevelGenerator.cpp` — генерация уровней с одной целью пока может
  оставлять список из одного элемента;
- `docs/level-authoring.md`, `docs/game.md`, `docs/architecture.md`;
- `data/levels/*.lvl` не обязаны меняться: один `answer` остаётся валидным.

## Риски

- Легко перепутать «подмножество» и «точное совпадение»; в отчёте `--check`
  нужно писать явно.
- Дубликаты целей могут случайно сделать уровень нерешаемым; линт должен
  предупреждать.
- `hint` для нескольких целей может быть длиннее и дороже; нужен лимит.
- Старые сохранения и генератор не должны сломаться от смены `Num` на
  `vector<Num>`.
- Многострочные `description` в построчном `.lvl` неудобны; лучше sidecar.
