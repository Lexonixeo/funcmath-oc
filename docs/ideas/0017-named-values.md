# 0017. Именованные числа и структурные значения

**Статус:** частично реализовано (имена-метки)
**Сложность:** высокая

## Что уже реализовано

В `.lvl` можно задать имя числа:

```text
number natural 3 as x
number natural 4 as y
```

Имя — это **метка**: его можно вводить вместо значения, оно отображается в
наборе (`x=3(natural)`), но решатель по-прежнему видит только значения и
считает одинаковые числа взаимозаменяемыми. Имена уникальны; при ходе имя
исчезает вместе со своим числом, у результатов имён нет. `calc` тоже понимает
имена (не удаляя их).

## Имена-метки и имена-ресурсы

Нужно различать два режима:

- **Имена-метки** (реализованы): имя — удобный псевдоним значения. Состояние
  остаётся мультимножеством `Value`; `natural 2` и `integer 2` различимы по
  типу, а два одинаковых `natural 2` — нет. Имя влияет только на ввод/вывод и
  выбор конкретного экземпляра, но не на пространство поиска.
- **Имена-ресурсы** (будущий режим уровня): каждый именованный слот — отдельная
  сущность; даже два `natural 2` с разными именами различны. Тогда ключ
  состояния решателя включает имена и, возможно, занятость слотов. Это другая
  механика, её лучше включать флагом уровня, а не глобально.

## Неоднозначность `natural 2` / `integer 2`

Если в наборе есть оба типа с одним значением, голое `2` неоднозначно. Правила:

- `natural=2` и `integer=2` выбирают конкретное значение;
- имя (`n2`) тоже выбирает конкретное значение;
- голое `2` при наличии обоих типов даёт ошибку с подсказкой;
- голое `2` при единственном подходящем типе выбирается как раньше;
- отображение смешанного набора показывает типы: `n2=2(natural) i2=2(integer)`.

В будущем можно добавить необязательный вывод типа из контекста, но для
пользовательских функций уже действует простое правило: bare-литерал — это
`integer`, а `natural` задаётся явно.

## Суть

Для векторов, матриц, записей и больших наборов чисел неудобно обращаться по
индексу: `[0, 3, 5, 31, 2, -1, 5, 7]`. Хочется именованные элементы и/или
именованные числа в наборе.

## Будущие механизмы

### 1. Имена-ресурсы в наборе уровня

Реализованные выше имена — только метки. Режим имён-ресурсов выглядел бы так:

```text
number natural 3 as x
number natural 4 as y
```

Тогда функцию можно вызвать по именам, а не по значениям. Это меняет
семантику набора:

- состояние — не мультимножество значений, а набор именованных слотов;
- одинаковые числа с разными именами становятся различимыми;
- решателю нужен ключ состояния с именами;
- игрок может использовать конкретное число, даже если есть такое же;
- уровни становятся более «головоломочными», но менее свободными.

Плюсы: удобно для векторов и матриц, где важен смысл элемента.
Минусы: сложнее решатель, больше состояние, ломается текущая модель
«числа взаимозаменяемы».

Это можно сделать необязательным режимом уровня, а не глобальным изменением.

### 2. Локальные имена в функциях

Уже решено параметрами и временными переменными:

```text
in v: vector
body
  x = at v 0
  y = at v 1
```

Это не меняет набор: имена живут только внутри функции.

### 3. Поля структурного значения

```text
point = vec3 x=0 y=3 z=5
x = point.x
```

или запись:

```text
point = {x: 0, y: 3, z: 5}
```

Для матриц:

```text
a = at m 0 1      # строка 0, столбец 1
row = row m 0
```

Это ближе к векторам/матрицам, чем имена в наборе.

## Рекомендация

1. Имена-метки уже есть — оставить их как удобный слой ввода/вывода.
2. Следующий шаг — структурные значения с индексами/полями (`at`, `.x`, срезы).
3. Имена-ресурсы — только как отдельный режим уровня, если появится механика,
   где важно различать одинаковые числа.
