# AGENTS.md

Короткая инструкция для ИИ-агентов и людей, которые продолжают проект
func(math). Подробное состояние проекта и план — в
[docs/ai-context.md](docs/ai-context.md).

## Что это за проект

Консольная игра-головоломка на C++17: из набора чисел нужно получить заданное
число, применяя функции. Уровни лежат в `data/levels/*.lvl`.

Основные документы:

- [README.md](README.md) — обзор, сборка, запуск;
- [docs/gameplay.md](docs/gameplay.md) — полное руководство игрока;
- [docs/game.md](docs/game.md) — техническое описание игры;
- [docs/level-authoring.md](docs/level-authoring.md) — формат уровней;
- [docs/level-design.md](docs/level-design.md) — принципы создания уровней;
- [docs/architecture.md](docs/architecture.md) — устройство кода.

## Сборка и проверка

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Для быстрой локальной сборки на Windows с MinGW:

```bat
build.bat
```

Проверка конкретного уровня:

```sh
./funcmath --check N
```

Не считайте `--check` доказательством хорошего уровня: он ищет только какой-то
путь. Человеческая длина решения и задумка проверяются отдельно.

## Инварианты проекта

- Язык выражений: каноническая префиксная запись; инфикс — синтаксический
  сахар, который нормализуется в префикс.
- Старые префиксные выражения должны продолжать работать.
- `natural` — строгий неотрицательный тип; отрицательный результат `natural`
  является ошибкой.
- Тип хранится у конкретного значения, а не у всего набора.
- Пользовательские функции интерпретируются; структура проверяется при
  загрузке, типы и домены — при вычислении.
- Ошибка вычисления не должна менять набор уровня.
- Поток результатов пока один; он должен быть последним результатом.
- Случайность: решатель перебирает исходы; `rand` — основной источник
  случайности.
- GUI и катсцены не входят в текущую задачу.
- Формат сохранений и номера уровней могут меняться, но такие изменения нужно
  явно документировать.

## Правила работы

- Перед существенными изменениями C++ и особенно перед массовой
  перенумерацией уровней — обсудить план с владельцем проекта.
- Не удалять незнакомые файлы и не перезаписывать пользовательские данные.
- Сохранять существующие уровни, если они не входят в согласованную чистку.
- Новые идеи и планы класть в `docs/ideas/` или в дорожную карту
  `docs/ai-context.md`.
- После изменения синтаксиса, типов или функций обновлять документацию и
  тесты.
- Коммиты делать небольшими и с понятным сообщением.
- Не добавлять секреты, токены и локальные пути в репозиторий.

## Текущее состояние

Инфиксная запись (`+ - * / % **`, скобки, `f(...)`) работает; после аудита
и перестройки курса — 72 уровня. Дубли удалены, `abs`/`not` стали унарными,
`avg`/`sumr`/`neg2`/`five`/`subr`/`mulr` задаются в уровнях, в игре есть
обучение и подробный `help`, а релизные архивы получают `.txt`-версии
документации. Лицензия проекта — MIT (`LICENSE`). Подробности — в
`docs/ai-context.md`, `docs/level-audit.md` и `docs/level-renumbering.md`.
