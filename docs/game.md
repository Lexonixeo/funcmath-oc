# func(math) — C++17

Порт консольной игры **func(math)** с Java (`github.com/Lexonixeo/funcmathjava1`) на C++17.
Геймплей сохранён, но проект переписан и разбит на модули, а данные уровней переведены
из Java-сериализации (`*.dat`) в читаемый текстовый формат (`*.lvl`).

Это подробная документация. Краткий обзор и структура репозитория — в
[`../README.md`](../README.md). Полное руководство игрока — в
[`gameplay.md`](gameplay.md).

## Возможности

- 85 уровней: 40 оригинальных, 16 новых (41–56), 6 из раннего прототипа
  (57–62), 16 из Java-прототипа (63–78), учебный уровень 79 и шесть новых
  черновиков (80–85).
- Типы значений `natural` и `integer` (у каждого числа свой тип).
- Пользовательские функции, собранные из простейших: параметры, выходы,
  временные переменные, потоки, перегрузки и случайность.
- Необязательные имена чисел в наборе (`number natural 3 as x`).
- 23 простейшие функции: арифметика, побитовые операции, конкатенация, системы
  счисления, разложение на простые множители и др.
- Функции произвольной арности и с несколькими результатами; вложенные
  префиксные выражения.
- «Неизвестные» функции: игрок видит имя, но не знает поведение.
- История ходов (`history`) и показ текущего набора после каждого хода.
- Аккаунты, сохранения, статистика, оценки сложности уровней.
- Подсказка (`hint`) на основе встроенного решателя.
- Генератор случайных уровней и режимы создания уровней (`--author`) и
  функций (`--function`).
- Проверка решаемости всех уровней (`--check`).

## Отличия от Java-версии

- Полностью переписан на C++17, без внешних зависимостей.
- Исходники разбиты по файлам (см. «Структура»).
- Уровни хранятся в текстовых `data/levels/levelN.lvl` вместо `*.dat`.
- Доработаны бывшие заглушками функции: `random`, `stats`, `hint`.
- Добавлены режимы `--check` и `--author`.
- Объединён с ранним C++-прототипом: добавлены `history`, показ остатка набора
  после хода, `cls` и 6 уровней со скрытыми функциями `five`/`neg2`.
- Исправлен `last`: в Java он открывал текущий уровень заново, хотя подсказка
  обещает предыдущий.
- Арифметика на 64-битных значениях с насыщением на ±1e18 и делением на ноль → 0
  (в Java использовались `Integer.MAX_VALUE/MIN_VALUE`, что давало переполнения и UB).
  `natural` не может быть отрицательным: вычитание большего из меньшего — ошибка.
- Исправлено зацикливание ввода при неверном пароле и EOF.
- `chcp`/`cls` больше не запускают `cmd.exe` (иначе «съедался» перенаправленный stdin).

|------|------------|

| `src/Value.h` | типизированное значение `natural`/`integer` |

| `src/Expression.*` | инфиксная запись и её нормализация в префикс |
| `src/Function.*` | функция уровня: известная, неизвестная, пользовательская |
| `src/LevelStore.*` | формат `.lvl`, загрузка/сохранение, блоки функций |
| `src/Level.*` | игровой цикл уровня и его команды |
| `src/Solver.*` | ограниченный DFS-решатель (для `hint` и `--check`) |
| `src/LevelGenerator.*` | случайные уровни и интерактивное создание |
| `src/Player.*` | аккаунты и сохранения |
| `src/Game.*` | меню и команды верхнего уровня |
| `data/levels/levelN.lvl` | уровни (1–40 из оригинала, 41–56 новые, 57–62 из раннего прототипа, 63–78 из Java-прототипа, 79 учебный, 80–85 черновики) |
| `data/functions.txt` | описания функций |

## Сборка

Через g++ (MinGW / Linux):

```sh
g++ -std=c++17 -Wall -Wextra -O2 -o funcmath \
    src/Helper.cpp src/Functions.cpp src/Expression.cpp src/Function.cpp \
    src/LevelStore.cpp src/Level.cpp src/Solver.cpp src/LevelGenerator.cpp \
    src/Player.cpp src/Game.cpp src/main.cpp
```

Через CMake:

```sh
cmake -S . -B build
cmake --build build
```

Каталог `data/` копируется рядом с бинарником автоматически (CMake).
Для Windows есть `build.bat`.

Игру нужно запускать из каталога, где находится `data/`
(или из `build/`, если CMake скопировал данные).

## Запуск

```sh
funcmath            # игра
funcmath --check    # проверить все уровни на решаемость
funcmath --check 18 --nodes 5000000 --time 10000
funcmath --author   # создать новый уровень
funcmath --function # интерактивный редактор пользовательской функции
```

### Команды главного меню

| Команда | Действие |
|---------|----------|
| `play` | продолжить с первого непройденного уровня |
| `level N` | открыть уровень N |
| `random D` | случайный уровень сложности D |
| `last` / `next` | предыдущий / следующий уровень |
| `stats` | статистика игрока |
| `help` | список команд |
| `exit` | выход |

### Команды внутри уровня

| Команда | Действие |
|---------|----------|
| `func a b` | применить функцию к числам `a` и `b` |
| `calc <выражение>` | посчитать, не изменяя набор |
| `nums` | показать текущий набор чисел |
| `history` | показать историю ходов |
| `hint` | подсказать ход (best-effort) |
| `back` | отменить последний ход |
| `reset` | начать уровень заново |
| `clear` / `cls` | очистить экран |
| `help` | справка |
| `exit` | выйти из уровня |

Выражение можно записать в привычной инфиксной форме: `1 + 2`,
`(1 + 2) * 3`, `sum(1, 2) + 3`. Старая префиксная запись `sum 1 2` тоже
работает; её используйте, когда нужен поток или несколько результатов.
Применив функцию, вы забираете её аргументы из набора и добавляете результат.

## Формат уровня `.lvl`

Новый формат с типами:

```
# комментарий
number natural 3
number natural 4
number natural 5
answer natural 12
function sum
function A unknown mul
```

Старый формат без типов тоже поддерживается: все числа и ответ считаются
`integer`.

```
numbers 1 2 34
answer 1234
function conc
```

- `number <тип> <значение>` — одно число набора; тип `natural` или `integer`;
- `number <тип> <значение> as <имя>` — число с необязательным именем;
- `numbers ...` — старый компактный формат, все числа `integer`;
- `answer [<тип>] <значение>` — целевое число;
- `function <имя>` — известная функция;
- `function <имя> unknown <поведение>` — функция со скрытым поведением:
  игрок видит только имя, а работает она как `<поведение>`;
- `function <имя> file <файл>` — подключить пользовательскую функцию из
  `data/functions/<файл>.fn`;
- блок `function <имя> … end` — пользовательская функция (см. выше).

`natural` — неотрицательный тип: отрицательные значения в файле запрещены, а
операции, дающие отрицательный результат, считаются ошибкой. `integer` —
обычный знаковый 64-битный тип. Старые уровни остаются `integer`; новые
уровни прототипа используют `natural` там, где это уместно.

## Функции

```
sum  sub  mul  div  mod  abs  pow  rand
and  or   not  xor  avg  conc base round
sumr subr mulr divr
primes
five neg2
```

`sumr/subr/mulr/divr` — версии с погрешностью, `rand` — случайная.
`primes` — унарная функция: возвращает простые множители числа (может вернуть
несколько результатов). `five` (всегда 5) и `neg2` (`-a + 2`) — поведения из
раннего прототипа; они нужны для уровней 57–62 и не попадают в генератор
случайных уровней. Старые функции `abs`/`not` пока остаются бинарными: второй
аргумент игнорируется, чтобы не ломать уровни 23, 44 и 57.

Решатель работает и со случайными функциями: он перебирает все возможные
исходы, поэтому найденное решение означает «достижимо при удачном исходе».

## Пользовательские функции

Функция собирается из простейших и записывается блоком прямо в `.lvl`:

```
function divmod
  description divmod(a, b) -> q, r
  in a: integer
  in b: integer
  out q: integer
  out r: natural
  body
    q = div a b
    r = mod a b
end
```

Синтаксис:

- `function <имя>` … `end` — блок; `description` необязателен;
- `in <имя>: <тип>` — параметр, можно повторять;
- `out <имя>: <тип>` — выход; `out <имя>: <тип>...` — поток из 0+ значений
  (только один и только последним);
- `use <алиас> = <функция> <типы> -> <результаты>` — выбор конкретной
  перегрузки/сигнатуры, например
  `use sumNat = sum natural natural -> natural`;
- `body` — последовательность присваиваний; каждое имя вычисляется один раз;
- `q, r = divmod a b` — деструктуризация фиксированного результата;
- выход обязан получить значение ровно один раз; временные переменные можно
  использовать в следующих строках;
- `take n expr` — ровно первые `n` результатов (иначе ошибка), `drop n expr` —
  остаток, `first expr`, `rest expr`, `count expr` — работа с потоком;
- перегрузки по типам входов: можно объявить несколько `function` с одним
  именем и разными `in`-типами. Точное совпадение важнее расширения
  `natural -> integer`;
- случайность (`rand`, `sumr`, …) делает функцию нестабильной; это
  распространяется по вызовам и учитывается решателем.

`body` — это интерпретируемый `let*`: типы проверяются во время вычисления, а
не при загрузке. Ошибка типа/домена не роняет игру: `calc`, игра и `--check`
получают сообщение с именем функции и строкой тела; решатель просто
отбрасывает неудачный исход. Структура блока (неизвестный ключ, незаполненный
выход, повторное имя, неправильный `use`) проверяется при загрузке.

### Редактор и файлы функций

`funcmath --function` — консольный аналог `FunctionMakerPanel`: команды `name`,
`description`, `in`, `out`, `use`, `body`, `list`, `validate`, `test`, `save`.
Сохранённый файл `data/functions/<имя>.fn` можно подключить к уровню:

```
function myfn file myfn
```

Внутри блока и в выражениях уровня доступны те же простейшие функции. Файлы
функций переносимы: это обычный текст в формате блока, а не Java-сериализация.

Пока не реализованы `sort`/`shuffle`, `if`/`bool`, несколько потоков и
статическая проверка типов; `abs`/`not` остаются бинарными ради старых уровней.

## Выражения и арность

Есть две записи. Префиксная — историческая и основная для потоков: функция
сама знает, сколько аргументов ей нужно; аргументом может быть число из набора
или другое выражение:

```
sum 1 3
sum 1 sum 2 3
mul 3 mul 7 11
primes 30
```

Инфиксная — синтаксический сахар для привычной математики. Поддерживаются
`+`, `-`, `*`, `/`, `%`, `**`, скобки и вызовы функций с аргументами через
запятую:

```
1 + 3
(1 + 2) * 3
2 ** 10
sum(1, 3) + 4
mul(3, 7) + 11
```

Правила:

- `+` → `sum`, `-` → `sub`, `*` → `mul`, `/` → `div`, `%` → `mod`,
  `**` → `pow`; соответствующая функция должна быть доступна в уровне;
- `*`, `/`, `%` и `**` приоритетнее `+` и `-`; `**` правоассоциативен;
- унарный минус допускается только перед числом: `-3`, `1 - -2`; для
  типизированного литерала пишите `integer=-3`;
- в инфиксном выражении вызов функции записывается как `f(1, 2)`;
- нельзя смешивать в одном выражении префиксный вызов и инфикс:
  `sum 1 2 + 3` — ошибка, `sum(1, 2) + 3` — правильно;
- `^` не является степенью; используйте `**` или `pow`.

При выполнении выражения из набора удаляются все числа-листья, а в набор
добавляются результаты корневой функции. Вложенное выражение эквивалентно
последовательности обычных ходов, но записывается одной строкой. `calc`
разбирает такое же выражение, не меняя набор.

### Типизированные литералы и имена

Если в наборе есть `natural 2` и `integer 2`, голое `2` неоднозначно. Тогда
используйте явный литерал:

```
natural=2
integer=2
```

Внутри пользовательских функций bare-литерал (`-1`, `2`) считается `integer`;
`natural=2` нужен, когда важна именно natural-перегрузка. При присваивании
выходу выполняется проверяемое приведение: `integer` в `natural` допустим
только для неотрицательного значения.

Число в наборе может иметь имя:

```
number natural 3 as x
```

Имя — это метка для ввода/вывода: `x` можно писать вместо `3`; в смешанном
наборе отображается `x=3(natural)`. Решатель по-прежнему считает одинаковые
числа взаимозаменяемыми, то есть имя не меняет пространство поиска. `calc`
тоже понимает имена и не удаляет их.

Если функция возвращает несколько результатов (`primes`), все они добавляются
в набор. Внутреннее выражение с несколькими результатами может заполнить
несколько аргументов родительской функции; например, `mul primes 77` — это
`mul 7 11`.

## Уровни

- **1–40** — из оригинальной Java-версии (формат переведён из `*.dat`).
- **41–56** — новые: побитовые операции (`and`/`or`/`xor`/`not`), `conc`, `base`
  и уровни с «неизвестными» функциями.
- **57–62** — из раннего однофайлового прототипа: скрытые функции `A`/`B`
  с поведениями `five` и `neg2`. Уровень 60 в прототипе был нерешаемым
  (цель 15), поэтому его цель заменена на достижимую `-25`.
- **63–78** — 16 уровней Java-прототипа: первые 13 на `natural`, последние
  3 на `integer`. Названия и авторские подсказки сохранены в
  `docs/prototype/levels.md`; в игре `hint` пока вычисляется решателем.
  Уровень 68 («Слепота») содержит 142 числа и проверяет устойчивость
  решателя к большим мультимножествам.
- **79** — учебный уровень: именованное число, пользовательская функция с
  потоком, `first`/`rest` и typed-литерал. Подробный разбор — в
  [`level-authoring.md`](level-authoring.md).
- **80–85** — черновики новых уровней: алгоритм Евклида, возведение в степень
  повторным умножением, выбор множителей, битовая маска, частное и остаток,
  скрытая пользовательская функция `glue`.

## Особенности и ограничения

- Пользовательские функции пока интерпретируются: проверка типов и домена идёт
  во время вычисления, а не при загрузке. Ошибки не роняют игру, но полного
  стека вызовов и кодов диагностики пока нет.
- `sort`/`shuffle`, `if`/`bool`, несколько потоков и статическая типизация тел
  функций — следующие этапы. `take`/`drop`/`first`/`rest`/`count` работают в
  телах функций; в выражениях уровня они пока не являются обычными функциями.
- Имена чисел — метки для ввода/вывода; решатель не различает одинаковые числа
  с разными именами.
- `hint` — эвристика: для особо сложных уровней может не найти решение за лимит.
- Случайные функции (`rand`, `sumr`, …) решатель перебирает полностью: уровень
  считается решаемым, если цель достижима при каком-то исходе. Для игрока это
  значит «нужна удача/несколько попыток», и `hint` об этом предупреждает.
  Вся стратегия перебора собрана в `fmath::outcomes` (`src/Functions.cpp`) —
  её легко заменить, не трогая решатель.
- Уровень 18 (найти `2048` из `1..14,35,99,105,117` через `div`/`mul`) решаем,
  но обычный DFS находит его не сразу. Решение вручную:
  `mul 6 12=72; div 72 9=8; div 10 5=2; div 14 7=2; mul 2 4=8;`
  `mul 8 8=64; mul 64 2=128; mul 128 2=256; mul 256 8=2048`.
- Уровень 32 решается благодаря целочисленному (усекающему) `avg`.
- `round` для целых чисел не меняет значение (все числа уже целые).
