# Руководство: уровни `.lvl` в Блокноте

Это практическое руководство для тех, кто пишет уровни вручную в Windows
Блокноте. Оно описывает текущий формат `.lvl`, пользовательские функции,
типы, имена чисел и типичные ошибки.

Готовый пример, который использует многие новые возможности, —
`data/levels/level79.lvl`.

## 1. Где лежат уровни

Уровни находятся здесь:

```text
data/levels/levelN.lvl
```

Например, `data/levels/level79.lvl`. Номер в имени файла — это номер уровня.
Игра сама находит все файлы `level*.lvl` и сортирует их по номеру.

Запускать игру нужно из каталога, где есть `data/` (обычно корень репозитория),
или из каталога сборки, куда CMake скопировал `data/`.

## 2. Создание файла в Блокноте

1. Откройте папку `data\levels`.
2. Запустите Блокнот.
3. Вставьте текст уровня.
4. `Файл → Сохранить как…`.
5. Перейдите в `data\levels`.
6. В поле «Тип файла» выберите **Все файлы (*.*)**. Иначе Блокнот может
   сохранить `level79.lvl.txt`.
7. В поле «Имя файла» напишите `level79.lvl`.
8. В поле «Кодировка» выберите **UTF-8** (без BOM).
9. Сохраните.

Почему важен UTF-8 без BOM:

- игра читает файл как байты и не удаляет BOM;
- BOM в начале файла может превратить первую строку в «неизвестный ключ»;
- русские комментарии и `description` в другой кодировке могут отображаться
  «кракозябрами».

Если в списке кодировок есть отдельный пункт «UTF-8 с BOM», не выбирайте его:
нужен просто «UTF-8». Если при сохранении в UTF-8 первая строка всё равно
вызывает ошибку «неизвестный ключ», проверьте, не добавил ли редактор BOM.

Расширение `.lvl` важно: файл `level79.txt` игра не увидит.

## 3. Минимальный уровень

Самый простой уровень:

```text
# комментарий
number natural 1
number natural 1
answer natural 2
function sum
```

Что здесь есть:

- два числа в наборе;
- цель `2`;
- функция `sum`.

Проверка:

```sh
funcmath --check 79
```

Если уровень решаем, команда покажет число ходов. Для одного уровня код
возврата обычно `0`; общий `--check` по всем уровням может вернуть `1`
из-за известного ограничения уровня 18.

## 4. Числа

### 4.1. Типизированные числа

```text
number natural 3
number integer -5
```

- `natural` — неотрицательное целое;
- `integer` — знаковое целое.

`natural` строгий: отрицательное значение нельзя записать в файле, а
операция, дающая отрицательный `natural`-результат, считается ошибкой
выполнения. Ошибка не роняет игру: выводится сообщение, набор не меняется.

### 4.2. Старый компактный формат

```text
numbers 1 2 34
answer 1234
```

Здесь все числа считаются `integer`. Старые уровни можно не переписывать.

### 4.3. Имена чисел

```text
number natural 84 as n
```

Теперь `n` можно писать вместо `84`:

```text
split n
```

Имя — это **метка**:

- имя уникально в пределах уровня;
- при ходе имя исчезает вместе с числом;
- у результатов имён нет;
- решатель видит только значения, поэтому имена не меняют пространство поиска;
- `calc` тоже понимает имена и не удаляет их.

В смешанном наборе отображается тип:

```text
n=84(natural) 5(integer)
```

Если в наборе есть `natural 2` и `integer 2`, голое `2` неоднозначно.
Выбирайте явно:

```text
natural=2
integer=2
```

Или используйте имя конкретного числа.

## 5. Ответ

```text
answer natural 42
number integer 10
answer integer -3
```

Тип у `answer` необязателен в старом формате:

```text
answer 42
```

Ответ — обычное значение с типом. `natural`-ответ не может быть
отрицательным.

## 6. Обычные функции уровня

### 6.1. Известная функция

```text
function sum
function mul
function primes
```

Имя должно быть в реестре простейших функций. Игрок увидит описание из
`data/functions.txt`.

### 6.2. Неизвестная функция

```text
function A unknown mul
```

Игрок видит только `A`, но реально она работает как `mul`. Это механика
«выясни поведение экспериментально».

## 7. Пользовательская функция

Блок функции:

```text
function divmod
  description divmod(a, b) — частное и остаток
  in a: integer
  in b: integer
  out q: integer
  out r: integer
  body
    q = div a b
    r = mod a b
end
```

Разбор:

- `function <имя>` — начало блока;
- `description` — необязательное описание для игрока;
- `in <имя>: <тип>` — параметр; строк `in` может быть несколько;
- `out <имя>: <тип>` — выход; строк `out` может быть несколько;
- `out <имя>: <тип>...` — поток из нуля или более значений;
- `body` — начало тела;
- `end` — конец блока.

Правила:

- у функции должен быть хотя бы один `out`;
- поток `...` может быть только один и только последним выходом;
- каждый выход должен получить значение ровно один раз;
- параметры, выходы и временные переменные имеют имена;
- имена не должны совпадать с именами функций и со специальными словами
  `take`, `drop`, `first`, `rest`, `count`;
- пользовательская функция не может переопределять встроенную функцию;
- блок должен быть закрыт `end`.

### 7.1. Тело как последовательность присваиваний

```text
body
  p = primes n
  head = first p
  tail = rest p
```

Каждое имя вычисляется один раз и доступно следующим строкам. Это похоже на
`let*` в функциональных языках.

Можно присвоить несколько результатов сразу:

```text
q, r = divmod a b
```

Но у потоков деструктуризация не поддерживается: поток нужно обрабатывать
через `take`, `drop`, `first`, `rest` или `count`.

В теле можно использовать инфиксную запись. Это тот же сахар, что и в
выражениях уровня:

```text
body
  s = a + b
  r = s * 2
  q = sum(1, 2) + 3
end
```

Правила те же: `+ - * / % **`, скобки, вызовы `f(...)`; нельзя смешивать
префиксный вызов и инфикс в одной строке. Старые префиксные тела
(`r = sum a b`, `r = take 2 p`) продолжают работать без изменений.

### 7.2. Работа с потоком

```text
p = primes n
firstPrime = first p
others = rest p
firstTwo = take 2 p
withoutFirst = drop 1 p
howMany = count p
```

- `first expr` — первый результат; пустой поток — ошибка;
- `rest expr` — все, кроме первого; пустой поток даёт пустой поток;
- `take n expr` — ровно первые `n`; если результатов меньше, ошибка;
- `drop n expr` — остаток после первых `n`;
- `count expr` — количество результатов, `integer`.

### 7.3. Типизированные литералы внутри тела

```text
r = mul n natural=2
```

Bare-литерал (`2`, `-1`) по умолчанию считается `integer`. Если нужна именно
natural-перегрузка, пишите `natural=2`.

При присваивании выходу выполняется проверяемое приведение:

- `natural` → `integer` разрешено;
- `integer` → `natural` разрешено только для неотрицательного значения;
- отрицательное значение в `natural`-выходе — ошибка выполнения.

### 7.4. Несколько перегрузок

Одна функция может иметь несколько блоков с одним именем и разными типами
входов:

```text
function double
  in n: natural
  out r: natural
  body
    r = mul n natural=2
end

function double
  in n: integer
  out r: integer
  body
    r = mul n integer=2
end
```

Точное совпадение типа важнее расширения `natural → integer`. Если
перегрузки неоднозначны, будет ошибка; помогает `use`-алиас.

### 7.5. Алиасы и выбор перегрузки

```text
function twice
  in n: natural
  out r: natural
  use sumNat = sum natural natural -> natural
  body
    r = sumNat n n
end
```

`use` выбирает конкретную сигнатуру. Аргументы алиаса проверяются: например,
алиас с `natural` не примет `integer`.

## 8. Функции из файла `.fn`

Функцию можно сохранить отдельно:

```sh
funcmath --function
```

В редакторе доступны команды `name`, `description`, `in`, `out`, `use`,
`body`, `list`, `validate`, `test`, `save`. Сохранение создаёт
`data/functions/<имя>.fn`.

Подключение к уровню:

```text
function myfn file myfn
```

Файл ищется в `data/functions/`. Если расширение не указано, добавляется
`.fn`. Внутри `.fn` — тот же блок `function ... end`, что и в уровне.

## 9. Готовый пример: уровень 79

```text
# func(math) level 79
# Тема: простые множители и пользовательские функции.
# split(n) возвращает первый простой множитель и поток остальных.
# Соберите 42 из множителей числа 84: 42 = 3 * 7 * 2.
# Решение: split n -> 2 2 3 7; mul 3 7 -> 21; double 21 -> 42.

number natural 84 as n
answer natural 42

function split
  description split(n) — первый простой множитель и остальные
  in n: natural
  out firstFactor: natural
  out restFactors: natural...
  body
    factors = primes n
    firstFactor = first factors
    restFactors = rest factors
end

function double
  description double(n) — удвоить natural-число
  in n: natural
  out r: natural
  body
    r = mul n natural=2
end

function mul
```

Что демонстрирует пример:

- `natural` и именованное число `n`;
- пользовательскую функцию;
- фиксированный выход + поток;
- `first` и `rest`;
- typed-литерал `natural=2`;
- несколько ходов.

## 10. Комментарии и форматирование

Комментарии начинаются с `#`:

```text
# это комментарий
number natural 3
```

Комментарии внутри блока тоже допустимы:

```text
function f
  # описание
  in n: natural
  out r: natural
  body
    # вычислить
    r = mul n natural=2
end
```

Отступы не обязательны, но два пробела делают блок читаемым. Пустые строки
игнорируются. Для отступов подойдут и пробелы, и табуляция.

## 11. Как проверить уровень

1. Сохраните файл.
2. Проверьте один уровень:

```sh
funcmath --check 79
```

3. Если решатель не нашёл решение за стандартный лимит, увеличьте лимиты:

```sh
funcmath --check 79 --nodes 5000000 --time 10000
```

4. Запустите игру и откройте уровень:

```text
level 79
```

5. Внутри уровня полезны команды:

```text
nums
hint
calc <выражение>
history
reset
```

`calc` считает выражение, не меняя набор. `hint` использует решатель и может
не найти решение для очень сложного уровня.

## 12. Частые ошибки

### «файл не найден» или уровень не появился

- файл лежит не в `data/levels/`;
- расширение `.txt` вместо `.lvl`;
- игра запущена не из каталога с `data/`.

### «неизвестный ключ в строке»

- опечатка в `number`, `answer`, `function`, `in`, `out`, `use`, `body`;
- BOM в начале файла;
- лишний текст в строке, где ожидается ключ;
- забыт `end` у блока функции.

### «уровень неполный»

- нет ни одного `number`/`numbers`;
- нет `answer`;
- нет ни одной `function`.

### «функция … ожидает … аргумент(ов)»

- у функции неверная арность;
- поток вернул больше/меньше значений, чем нужно родительской функции;
- для потока нужно использовать `take`, `first`, `rest` и т.п.

### «natural: отрицательный результат»

- `sub`/`mod`/другая операция дала отрицательное значение;
- выход объявлен `natural`, а выражение даёт отрицательный `integer`;
- нужен `integer`-выход или проверка значения.

### «имя значения совпадает с функцией»

- параметр/выход/временная переменная названы как функция;
- переименуйте переменную, например `n` вместо `sum`.

### «число … есть в наборе в нескольких типах»

- в наборе есть `natural 2` и `integer 2`;
- используйте `natural=2`, `integer=2` или имя числа.

## 13. Ограничения текущей версии

- Тела пользовательских функций интерпретируются, а не компилируются в AST:
  типы проверяются во время вычисления.
- `take`/`drop`/`first`/`rest`/`count` работают в телах функций, но не являются
  обычными командами уровня.
- `sort`/`shuffle`, `if`/`bool` и несколько потоков пока не реализованы.
- `abs`/`not` остаются бинарными ради старых уровней.
- Имена чисел — метки, а не отдельные ресурсы: два одинаковых числа с разными
  именами для решателя неразличимы.
- Ошибки выполнения не роняют игру, но не имеют полного стека вызовов.

## 14. Шаблон для копирования

```text
# func(math) level 80
# Краткое описание уровня.

number natural 10 as n
number natural 3
answer natural 13

function sum
function mul

function twice
  description twice(n) — удвоить число
  in n: natural
  out r: natural
  body
    r = mul n natural=2
end
```

Проверьте, что:

- имя файла — `level80.lvl`;
- кодировка — UTF-8 без BOM;
- `answer` действительно достижим;
- все блоки закрыты `end`;
- `--check 80` находит решение.
