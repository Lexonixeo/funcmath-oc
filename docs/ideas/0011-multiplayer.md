# 0011. Мультиплеер: кооператив и гонка

**Статус:** идея
**Сложность:** высокая

## Суть

Письмо руководителю предлагает мультиплеер: пошаговый кооператив или соревнование
«кто за меньшее число ходов получит требуемое». Это естественное продолжение
игры, но его лучше делать после браузерного UI (идея 0008).

## Режимы

### 1. Кооператив (turn-based co-op)

- Один уровень и один общий набор чисел.
- Игроки ходят по очереди; каждый видит ходы друг друга.
- Можно добавить «личные» числа: у каждого свой набор, цель общая.
- Чат, голосование за откат, таймер на ход (опционально).
- Победа — когда цель собрана; поражение — когда набор «сжался» и цель
  недостижима (если такое правило включено).

### 2. Гонка (race)

- Один и тот же уровень и seed случайности у всех.
- Побеждает тот, кто первым получит цель.
- Вариант: фиксированное время, побеждает решение с меньшим числом ходов.
- Лидерборды: время, число ходов, использованные подсказки.

### 3. Асинхронный режим

- «Уровень дня»: все решают один уровень, результаты сравниваются.
- Обмен решениями/повторами (см. идею 0012).

## Архитектура

Для честной игры нужен **авторитетный сервер**:

- сервер хранит комнаты, уровни, состояние партии;
- клиенты отправляют **ходы**, а не готовое состояние;
- сервер проверяет легальность хода и сам применяет функцию;
- клиент получает подтверждённое состояние или дифф;
- случайность детерминирована seed’ом, который знает сервер;
- переподключение — по snapshot + пропущенным ходам.

```
Клиент A ── ход ──► Сервер ── проверка ──► рассылка ──► Клиенты A, B
```

### Технологии

- WebSocket (JSON или бинарный протокол).
- Сервер: C++ (Asio/uWebSockets), Go или Node — что проще поддерживать.
- Комнаты по коду приглашения, матчмейкинг по сложности.
- Аутентификация: ник + токен; без сложной регистрации на MVP.

### MVP без сети

1. **Hot-seat** на одном компьютере: два игрока ходят по очереди.
2. **LAN** или прямой обмен по сети.
3. Только потом — интернет-сервер, аккаунты и рейтинг.

## Античит и честность

- Сервер — единственный источник истины.
- Проверять: числа есть в наборе, функция доступна, ход легален, цель достигнута.
- Ограничивать частоту ходов.
- Не доверять клиентскому «я победил».
- Seed случайности не раскрывать до конца партии (или использовать
  commit-reveal).

## Зачем

- Кооператив делает игру социальной и помогает учиться друг у друга.
- Гонка добавляет азарт и мотивацию оптимизировать решения.
- Асинхронные уровни дня удерживают интерес без постоянной игры.

## Что затронет

Новый каталог `server/`, `web/` (клиент), протокол в `docs/`,
возможно `src/` (выделение чистого ядра без консольного ввода-вывода).
Консольная версия может остаться офлайн-тренажёром.

## Риски

- Это самая большая по объёму идея: сеть, комнаты, синхронизация, античит.
- Хостинг и задержки.
- Сложно тестировать без инфраструктуры.
- Лучше не начинать, пока нет стабильного ядра и браузерного UI.
