# 0001. История ходов в виде дерева

**Статус:** идея
**Сложность:** средняя

## Суть

Сейчас история ходов — линейный список (`history`), а `back` просто удаляет
последний ход. Если игрок откатился и пошёл в другую сторону, старая ветка
теряется. Предлагается хранить **дерево исследованных состояний**:

- узел — набор чисел;
- ребро — ход (`sum 2 5 = 7`);
- текущий узел — то, что игрок видит как «набор»;
- `back` переходит к родителю, **не удаляя** детей;
- можно вернуться в любую исследованную ветку и продолжить её.

Пример вывода команды `tree`:

```
* [0] 1 2 3 4 5
├─ [1] sum 1 2 = 3        (3 3 4 5)
│  └─ [2] mul 3 3 = 9     (4 5 9)  ✔
└─ [3] sub 2 1 = 1        (1 3 4 5)
   └─ [4] div 4 1 = 4     (3 4 5)
```

`*` — текущий узел, `✔` — в наборе есть целевое число.

## Зачем

- Игрок видит, какие стратегии уже пробовал, и не повторяет их.
- Откат перестаёт быть «разрушительным»: можно сравнить две ветки.
- Это естественно подводит к идее поиска с возвратом (backtracking) — полезно
  для развития «думалки» и для будущего решателя.
- Можно показывать ветку, которую предлагает `hint`, и объяснять, почему она
  короче.

## Эскиз реализации

```cpp
struct Node {
    std::vector<Num> numbers;
    std::string move;          // "sum 2 5 = 7", пусто у корня
    int parent = -1;
    std::vector<int> children;
    bool solved = false;
};

std::vector<Node> tree_;
int current_ = 0;
```

- `history_` и `stack_` заменяются на `tree_` + `current_`.
- `useFunction` добавляет новый узел (или переиспользует существующий, если
  такой набор уже был у родителя).
- `back` → `current_ = tree_[current_].parent`.
- Новые команды:
  - `tree` — напечатать дерево (с ограничением глубины/ширины);
  - `goto N` — перейти к узлу N;
  - `prune N` — удалить поддерево (необязательно);
  - `reset` — вернуться к корню (дерево можно сохранить или очистить).
- Для сохранения партии дерево можно сериализовать в файл игрока; это
  необязательно на первом этапе.

## Риски

- Дерево быстро растёт; нужен лимит узлов и аккуратный вывод.
- При случайных функциях один и тот же набор может получаться с разной
  вероятностью — для дерева это не важно, но для `hint` важно.
