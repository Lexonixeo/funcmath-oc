# 0024. Паритет встроенных функций

**Статус:** идея
**Сложность:** средняя

## Что есть в C++

В реестре `src/Functions.cpp` сейчас 23 функции:

```text
sum sub mul div mod abs pow rand and or not xor avg
sumr subr mulr divr conc base round five neg2 primes
```

Из них `primes` — поток, `rand`/`sumr`/`subr`/`mulr`/`divr` — нестабильные,
`five`/`neg2` — легаси ради старых уровней, а `conc`/`base`/`round`/`avg` —
локальные расширения.

## Чего нет из Java

В `defaultpack` Java-прототипа зарегистрированы (в тех или иных типах):

| Функция | Арность | Типы в Java | Статус в C++ |
|---------|---------|-------------|--------------|
| `root` | 2 | natural, integer, rational, real, complex | нет |
| `log` | 2 | natural, rational, real, complex | нет; integer в Java бросает ошибку |
| `gcd` | 2 | natural, integer | нет |
| `lcm` | 2 | natural, integer | нет |
| `fact` | 1 | natural, integer, rational, real, complex | нет |
| `min` | 2 | natural, integer, rational, real | нет |
| `max` | 2 | natural, integer, rational, real | нет |
| `sign` | 1 | natural, integer, rational, real, complex | нет |
| `concat` | 2 | natural, integer | нет (есть `conc`) |
| `conj` | 1 | почти все типы | нет |
| `arg` | 1 | natural, integer, rational, real, complex | нет |
| `norm` | 1 | natural, integer, rational, real, complex | нет |
| `med` | 2 | rational | нет |
| `floor` | 1 | rational, real | нет |
| `ceil` | 1 | rational, real | нет |
| `num` | 1 | rational | нет |
| `den` | 1 | rational | нет |
| `sin/cos/tan` | 1 | real, complex | нет |
| `arcsin/arccos/arctan` | 1 | real, complex | нет |
| `arctan2` | 2 | real | нет |
| `re/im` | 1 | gaussian, complex | нет |

Кроме того, `abs` и `not` в Java **унарные**, а в C++ бинарные: так исторически
сложились уровни 23, 44 и 57. `concat` в Java — десятичная конкатенация, а
локальный `conc` делает то же самое, но с другой обработкой ошибок и
переполнения.

## Приоритеты

### 1. Целочисленные функции без новых типов

Самые дешёвые и полезные:

- `gcd`, `lcm` — уже обещаны в `README.md` и идее 0002, но отсутствуют в коде;
- `min`, `max` — простые, возвращают один из аргументов;
- `fact` — унарный факториал;
- `sign` — унарный знак `-1/0/1`;
- `root` — целочисленный корень;
- `concat` — новый алиас/функция с десятичной конкатенацией.

Их можно добавить, не трогая `Value` и решатель. Главное — аккуратно описать
домены и переполнение.

### 2. `abs`/`not` без поломки старых уровней

В Java это унарные функции. В C++ их бинарность закреплена уровнями. Варианты:

1. добавить унарные перегрузки, а бинарные оставить как легаси-алиасы;
2. завести новые имена (`abs1`, `not1`) и постепенно переписать уровни;
3. оставить бинарные и не считать это паритетом.

Предпочтителен первый вариант: `FunctionSpec` уже поддерживает несколько
сигнатур, но `buildRegistry` сейчас создаёт бинарные сигнатуры для всех
операций. Нужно вынести унарные функции в отдельные `FunctionSpec` и научить
`arity()`/`fn.numberOfArgs` выбирать сигнатуру.

### 3. Функции для числовой башни

После 0023:

- `conj`, `arg`, `norm` — для integer/natural они почти тривиальны, для
  rational/real/complex имеют настоящий смысл;
- `med` — медиант двух дробей (в Java `(a/b, c/d) -> (a+c)/(b+d)`), а не
  среднее; для rational;
- `floor`, `ceil`, `num`, `den` — для rational;
- `re`, `im` — для gaussian/complex;
- тригонометрия — только для real/complex и только с фиксированной точностью.

Не стоит переносить странные частные случаи Java вслепую. Например,
`FInteger.arg` возвращает `0` или `-4`, а `FNatural.arg` — всегда `0`. Это
историческая аппроксимация угла, а не нормальная математика; для C++ лучше
либо не добавлять `arg` до появления real/complex, либо определить его явно.

## Семантика, которую нужно зафиксировать

### `gcd` и `lcm`

- `gcd(a, b)` — неотрицательный; `gcd(0, 0) = 0`;
- `lcm(0, 0)` в Java делит на `gcd = 0` и падает; в C++ лучше вернуть ошибку
  домена или `0`, но выбрать одно и документировать;
- для integer знак `lcm` можно брать положительным, как `BigInteger.lcm` в
  математическом смысле;
- `natural` остаётся неотрицательным.

### `root`

- `root(radicand, degree)` — целочисленный корень (floor), как в Java;
- `degree = 0` — ошибка;
- отрицательный radicand и чётная степень — ошибка;
- отрицательный radicand и нечётная степень — отрицательный корень;
- для `natural` отрицательный radicand невозможен;
- реализация — бинарный поиск, без `pow` с переполнением.

### `log`

- `log(base, antilogarithm)` — целочисленный логарифм (floor);
- `antilogarithm = 0` — ошибка;
- `base = 0` или `base = 1` — ошибка;
- в Java для integer функция намеренно не реализована; в C++ можно сначала
  сделать только natural и вернуть понятную ошибку для integer.

### `fact`

- `fact(n)` — `n!`; `0! = 1`;
- отрицательное — ошибка;
- большие `n` быстро выходят за пределы; с BigInt (0023) предел ставится
  отдельно, без тихого насыщения.

### `min`/`max`

- возвращают один из аргументов, сохраняя тип;
- при равенстве Java возвращает первый; для значений это не важно, но полезно
  для стабильного вывода;
- для `natural`/`integer` сравнение точное.

### `sign`

- для `integer`/`natural` — `-1`, `0`, `1`; для `natural` только `0`/`1`;
- для `real`/`complex` знак может означать нормированное направление
  (`z / |z|`), а не только `-1/0/1`; это нужно определить вместе с 0023;
- тип результата: `natural` для natural, `integer` для integer; иначе
  возникает неоднозначность `natural=...`.

### `concat`

- десятичная запись: `12` и `3` дают `123`;
- Java для integer запрещает отрицательный второй аргумент;
- локальный `conc` при переполнении возвращает `0`, а Java использует BigInt;
- после 0023 `concat` должен работать без переполнения;
- для строк `concat` появится отдельно в 0009/0016, не путать с числовым.

### `abs`/`not`

- унарный `abs`: модуль; для natural — тождество;
- унарный `not`: побитовое отрицание, как в Java `BigInteger.not`;
- бинарные версии сохраняются только ради старых уровней; в описании функции
  это нужно явно помечать.

## Влияние на решатель

Новые функции расширяют branching:

- `fact`, `pow`, `lcm` могут давать очень большие числа;
- `root`/`log` — наоборот, сжимают;
- `min`/`max`/`sign` создают много дубликатов, но дешёвы;
- `concat` может порождать длинные числа.

Нужны:

- лимиты на величину результата (лучше через BigInt + явный предел, а не
  насыщение);
- запрет добавлять в генератор случайных уровней функции без шаблонов;
- проверка старых уровней через `--check` после изменения арности.

## Что затронет

- `src/Functions.cpp` — реестр, реализации, сигнатуры;
- `src/Function.*` — унарные перегрузки, `numberOfArgs`, отображение;
- `src/LevelGenerator.cpp` — пул генерации;

## Риски

- Нельзя молча менять арность `abs`/`not`: старые уровни перестанут решаться.
- `div`/`mod` на ноль в C++ возвращают `0`, в Java бросают исключение; новые
  функции не должны закреплять это расхождение без решения.
- `lcm(0,0)`, `root` с нулевой степенью, `log` по основанию 1 — пограничные
  случаи, которые легко пропустить.
- `fact`/`pow` без BigInt быстро упираются в предел.
- `concat`/`conc` — разные имена с почти одинаковым смыслом; нужна таблица
  совместимости.
- Новые функции увеличивают branching и время `--check`.
