# 0022. Категории уровней: default, custom и prelevels

**Статус:** идея
**Сложность:** средне-высокая

## Что есть в Java, но нет в C++

В Java уровни разделены на три категории через `PlayFlag`:

```java
enum PlayFlag {
    DEFAULT,   // карьера, уровни автора игры
    CUSTOM,    // пользовательские уровни
    PRELEVELS  // только что созданные, ещё не подтверждённые
}
```

`LevelRegister` хранит для каждой категории свой список номеров и свой каталог:

```text
data/levels/levelN.dat          DEFAULT
data/customLevels/levelN.dat    CUSTOM
data/preLevels/levelN.dat       PRELEVELS
```

Номер `ID` уникален только внутри категории, поэтому ключ уровня — это пара
`LevelPrimaryKey(ID, PlayFlag)`. От неё зависят:

- `getNextLevel` — следующий уровень ищется в списке той же категории;
- `Player.completedLevels`, `levelStates`, `levelStatistics` — прогресс и
  сохранения привязаны к паре, а не к одному числу;
- `getFirstUncompletedLevel` — сначала ищет незавершённый `DEFAULT`, затем
  `CUSTOM`;
- `addLevelInfo` — при совпадении ID в категории номер увеличивается, чтобы не
  перезаписать чужой уровень.

`DLMakerPanel` (мастер уровней) **задуман** так:

1. Новый уровень сохраняется как `PRELEVELS`.
2. Автор задаёт `futurePlayFlag` — `DEFAULT` или `CUSTOM`.
3. Команда `try` запускает черновик; после успешного прохождения ставится
   флаг «проверен».
4. `save` записывает уровень в каталог, соответствующий `futurePlayFlag`.
5. Если черновик не пройден, он остаётся в `PRELEVELS` и не попадает в
   карьеру или пользовательский список.

Важная оговорка: в текущем Java-коде проверка фактически отключена —
`isValidatedCompleted` инициализируется `true`, а часть сбросов этого флага
закомментирована. Поэтому `PRELEVELS` — это скорее проект механики, а не
готовый паритет. В C++ её стоит реализовать явно и с тестами, а не копировать
текущее поведение мастера.

В C++ сейчас один каталог `data/levels`, один `int number`, а `Player.completed`
и `lastLevel` — просто числа. Поэтому уровень с номером 5 из карьеры и
пользовательский уровень 5 неразличимы.

## Предлагаемая модель

### Каталоги

Сохранить имена Java, чтобы обмен уровнями и документация совпадали:

```text
data/levels/levelN.lvl          # DEFAULT, номера 1..79
data/customLevels/levelN.lvl    # CUSTOM, отдельная нумерация
data/preLevels/levelN.lvl       # PRELEVELS, черновики
```

`data/levels` остаётся каталогом по умолчанию. `customLevels` и `preLevels`
создаются при первом использовании.

Каталог — источник истины о категории. Дублировать её в `.lvl` не обязательно:
при копировании файла между каталогами категория меняется вместе с ним. Если
понадобится экспорт одного файла, можно добавить необязательный ключ
`playflag default|custom|prelevels`, но при загрузке из каталога он должен
совпадать с каталогом, иначе ошибка.

### Тип уровня

```cpp
enum class LevelKind { Default, Custom, Prelevel };

struct LevelKey {
    LevelKind kind = LevelKind::Default;
    int number = -1;
};
```

`LevelData` получает `LevelKind kind` (или `playFlag`) рядом с `number`.
`LevelKey` нужен для сравнения, сортировки и ключа сохранения.

Функции `levelstore` получают категорию:

```cpp
std::string levelPath(const std::string& dataDir, LevelKind kind, int number);
std::vector<int> listLevelNumbers(const std::string& dataDir, LevelKind kind);
int nextLevelNumber(const std::string& dataDir, LevelKind kind);
```

`--author` по умолчанию создаёт `PRELEVELS` и пишет в `preLevels`, а не сразу в
карьеру.

### Прогресс игрока

```cpp
struct Player {
    std::string name;
    std::set<LevelKey> completed;
    std::map<LevelKey, LevelStats> stats;
    LevelKey lastLevel;
    bool tutorial = true;
};
```

Для совместимости со старыми сохранениями:

- старые `completed N` и `last N` читаются как `Default/N`;
- в новый файл пишется явная категория: `completed default 5` или
  `completed custom 5`;
- если поле категории отсутствует, используется `Default`.

`PRELEVELS` не входят в общий прогресс: прохождение черновика — это проверка, а
не достижение. Статистику по черновику можно хранить отдельно или не хранить
вовсе.

### Поведение интерфейса

- `next` идёт по текущей категории; в конце `DEFAULT` можно предложить
  `CUSTOM`, но не смешивать списки молча.
- `last` восстанавливает и номер, и категорию.
- `map`/список уровней показывает три секции: карьера, пользовательские,
  черновики.
- `--check` по умолчанию проверяет `DEFAULT`; флаги `--custom` и
  `--prelevels` добавляют остальные категории.
- `--author` создаёт черновик; `--try N` проигрывает черновик без записи в
  прогресс; `--publish N [--custom|--default]` переносит проверенный черновик
  в выбранную категорию.
- Перенос `prelevel -> custom` — это перемещение файла (или копирование с
  удалением), а не смена номера. При конфликте ID выдаётся следующий свободный
  номер и это явно сообщается автору.

`--publish` должен отказываться публиковать непроверенный черновик. Проверка
может быть автоматической (`--check`) или ручной (`--try`), но факт проверки
нужно хранить: например, в sidecar-файле `preLevels/levelN.confirmed` или в
отдельном индексе. Иначе после перезапуска нельзя отличить проверенный
черновик от нового.

## Почему это не только «красивые папки»

Категория меняет:

- пространство номеров и следующую цель;
- ключ прогресса и статистики;
- поведение `last`/`next`;
- то, какие уровни видит игрок и какие проверяет `--check`;
- правила публикации и модерации (0012).

Если оставить один `int`, рано или поздно пользовательский уровень 5 перетрёт
карьерный уровень 5 или прогресс смешается.

## Поэтапный план

1. Ввести `LevelKind`, `LevelKey` и отдельные пути; старые уровни читать как
   `DEFAULT`.
2. Перевести `Player` на ключи с категорией и миграцию старых сохранений.
3. Добавить `customLevels` и `preLevels` в `--check`, список и `next`.
4. Разделить `--author` на черновик, `--try` и `--publish`.
5. Только после этого — браузерный редактор и галерея (0012).

## Что затронет

- `src/LevelStore.*` — пути, категории, списки, запись;
- `src/Player.*` — ключ прогресса, миграция сохранений;
- `src/Game.*` — `next`/`last`/`map` и загрузка категории;
- `src/LevelGenerator.cpp` — `--author`, `--try`, `--publish`;
- `src/main.cpp` — флаги проверки;
- `data/customLevels/`, `data/preLevels/`;
- `docs/game.md`, `docs/level-authoring.md`, `docs/architecture.md`.

## Риски

- Миграция сохранений: нельзя потерять старый прогресс.
- Одинаковые имена файлов в разных каталогах; нужен явный ключ.
- Черновики могут быть неполными; парсер сейчас требует числа, цель и функцию,
  поэтому «сохранить черновик» придётся либо ослабить, либо хранить отдельно.
- Публикация может случайно перезаписать уровень; нужна проверка конфликтов.
- `PRELEVELS` не должны попадать в статистику и достижения.
- Пользовательские уровни могут быть нерешаемыми; `--publish` должен
  предупреждать, а не молча принимать.
