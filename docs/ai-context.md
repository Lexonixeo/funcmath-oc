# Контекст проекта для ИИ-агента

Это рабочая «точка входа» для новой сессии: что уже сделано, какие решения
приняты, что делать дальше и где могут быть ловушки. Файл нужно обновлять в
конце крупных этапов.

Последнее обновление: 2026-10-22, после аудита уровней и UX-чистки. Изменения
ещё не закоммичены: перед коммитом нужно согласовать лицензию.

## 1. Кратко о проекте

func(math) — консольная игра-головоломка на C++17. Уровень задаёт набор чисел,
доступные функции и цель. Игрок вводит выражение; функция забирает аргументы
из набора и добавляет результаты.

Проект — C++-порт Java-прототипа. Геймплей сохранён, данные переведены в
текстовый формат `.lvl`. GUI и катсцены не входят в текущую задачу.

## 2. Быстрые команды

```sh
# Сборка
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release

# Тесты
ctest --test-dir build -C Release --output-on-failure

# Один уровень
./funcmath --check 60

# Все уровни
./funcmath --check
```

На Windows с MinGW:

```bat
build.bat
```

## 4. Что уже реализовано

- Типы `natural` и `integer`, typed-литералы `natural=2`, `integer=-3`.
- Имена чисел (`number natural 3 as x`) и неоднозначные числа.
- Префиксные выражения, вложенные вызовы, потоки результатов.
- `take`, `drop`, `first`, `rest`, `count`.
- Пользовательские функции: параметры, выходы, локальные переменные,
  перегрузки, `.fn`, `--function`.
- Случайность и перебор исходов в решателе.
- Инфиксная запись как сахар: `+ - * / % **`, скобки, `f(...)`,
  приоритеты, правая ассоциативность `**`.
- Нормализация тел функций вторым проходом, когда известны все функции и
  алиасы.
- `--check`, `--author`, `--function`.
- 72 уровня: базовый курс (1–36), побитовые и строки (37–45), случайность
  (46–52), неизвестные и скрытые функции (53–61), `natural` и теория чисел
  (62–70), пользовательские функции и потоки (71–72), финальный уровень (72).

## 5. Текущие решения и ограничения

- Префиксная запись остаётся канонической. Инфикс не вычисляется отдельно, а
  переписывается в префиксные слова.
- Старые префиксные формы должны работать: `sum 1 2`, `sum 1 -2`,
  `sum(1,2)`.
- Нельзя смешивать префиксный вызов и инфикс в одном выражении.
- `+`/`-`/`*`/`/`/`%`/`**` не являются самостоятельными операциями: они
  вызывают `sum`/`sub`/`mul`/`div`/`mod`/`pow`, которых может не быть в уровне.
- Унарный минус разрешён только перед числом; отрицательный typed-литерал —
  `integer=-3`.
- Внутри пользовательских функций bare-литерал считается `integer`; в
  уровне `calc` bare-литерал получает тип по умолчанию от набора.
- `div` при делении на ноль возвращает `0` — историческое поведение Java.
- Ошибка разбора/вычисления не должна менять `pool_`.
- Решатель ограничен по времени/узлам; `--check` не доказывает
  «человеческую» сложность.

## 6. Известные проблемы

- Уровень 18 (2048) решается только с увеличенным лимитом (`--nodes 50000000
  --time 60000`, около 15–20 секунд, путь из 16 ходов). Это кандидат на
  упрощение: для игрока задача может быть перебором, а не идеей.
- Полный `--check` с обычным лимитом всё ещё возвращает код 1 из-за уровня 18;
  CTest запускает его отдельно с увеличенным лимитом.
- Уровни 51 и 52 (бывшие 34 и 37) смешивают `rand` с `avg` и выглядят как
  лотерея; их стоит переписать, когда появится проверка ответа с допуском.
- Уровень 71 («Слепота») содержит 142 числа; решатель справляется, но для
  игрока это утомительно. Кандидат на сокращение набора.
- Уровень 63 (бывший 82) решатель проходит за 26 ходов из-за порядка поиска;
  человеческое решение короче. `--check` показывает верхнюю оценку, а не
  минимальную длину.
- CTest содержит тесты парсера и по одному тесту на уровень. Уровень 18
  использует повышенный лимит; `FM_KNOWN_UNSOLVABLE_LEVELS` пуст.
- CI уже проверяет сборку и тесты на Windows/Linux/macOS; релизный workflow
  собирает архивы по тегу `v*`.

## 8. Правила для агента

- Перед существенными изменениями C++ и перед массовой перенумерацией уровней
  нужно согласование с владельцем.
- Не удалять незнакомые файлы и не перезаписывать пользовательские данные.
- Сохранять существующие уровни, если они не входят в согласованную чистку.
- После изменения синтаксиса/функций обновлять `docs/gameplay.md`,
  `docs/game.md`, `docs/architecture.md` и тесты.
- Новые идеи складывать в `docs/ideas/` или в этот файл.
- Коммиты — небольшими этапами.
- Не добавлять секреты и локальные абсолютные пути.

## 9. Решения по релизам

- Имя артефактов: `funcmath-ds-vX.Y.Z-<os>-<arch>`.
- CI запускается на push в `main` и на pull request.
- Релиз создаётся по тегу `v*` (например, `v0.2.0`); ручной запуск
  `workflow_dispatch` собирает артефакты без публикации.
- В релиз входят исполняемый файл, `data/`, README и документация.
- Лицензия проекта — MIT; файл `LICENSE` в корне репозитория, SPDX-заголовки
  в исходниках.
- Требования к системе указаны в README, который входит в архив.
