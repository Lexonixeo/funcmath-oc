# 0019. Диагностика ошибок выполнения

**Статус:** частично реализовано
**Сложность:** средняя

## Что уже реализовано

- структурные ошибки блока (неизвестный ключ, незаполненный выход, повторное
  имя, неправильный `use`) сообщаются при загрузке с именем функции и строкой;
- ошибки выполнения не роняют игру: `calc`/игра печатают сообщение, решатель
  отбрасывает неудачный исход;
- для ошибки в теле показываются имя функции и строка `body`, например:
  `функция bad: в строке "r = sub n natural=5": ...`;
- у ошибок нет кодов, полного стека вызовов и подсветки позиции.

## Суть

Ошибка типа или `natural`-сужения не должна ронять игру. Нужно показать, где
именно она возникла: в каком выражении, в какой функции, с какими аргументами.
При этом не раскрывать лишнего в мультиплеере.

## Модель

```cpp
struct Diagnostic {
    Severity severity;        // error / warning
    std::string code;         // type_mismatch, natural_negative, arity...
    std::string message;
    std::string file;
    int line = 0;
    std::string function;     // divmod
    std::string expression;   // r = mod a b
    std::vector<std::string> stack; // divmod -> ...
    std::vector<Value> args;
};
```

Уровни детализации:

1. **Кратко:** «нельзя: `mod a b` даёт integer, а выход `r` — natural».
2. **С выражением:** показать строку `body` и подчеркнуть/выделить место.
3. **Со стеком:** `divmod -> r = mod a b -> mod`.
4. **С аргументами:** значения и типы на каждом шаге.

В консоли можно печатать кратко и предлагать `details`, либо показывать
развёрнуто в `calc`/`--author`.

## Типы ошибок

- **Компиляция:** неизвестная функция, несовпадение арности, типа, количества
  выходов, цикл, необъявленный выход, повторное связывание.
- **Выполнение:** деление на ноль, отрицательный `natural`, `take` получил
  меньше элементов, не хватило аргументов, перегрузка не найдена, исчерпан
  лимит `uses` (0020), запрещённые `back`/`calc`.
- **Правила уровня:** нарушение `allowBack`/`allowCalc`, невозможность
  использовать число из-за `infinityNumbers`, несовпадение категории и
  каталога (0022).
- **Решатель:** ошибка — не повод падать; исход отбрасывается, но для
  `--check`/автора сохраняется причина. Для нескольких целей (0021) полезно
  показывать, какие цели уже собраны, а каких не хватает.

## Мультиплеер

Сервер не должен отдавать клиенту тело скрытой функции в тексте ошибки.
Сообщение должно быть нейтральным: «функция A не приняла аргументы» без
раскрытия определения. Подробности — только автору/серверу.

## Что затронет

`src/Level.*`, `src/Function.*`, `src/Functions.*`, `src/Solver.*`,
`src/main.cpp`, `src/LevelStore.*`, будущий UI.

## Риски

- слишком длинные ошибки;
- утечка скрытых функций;
- разная диагностика у компиляции и выполнения.
