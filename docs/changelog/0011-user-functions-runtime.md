# 0011. Пользовательские функции: runtime-интерпретатор и редактор

**Дата:** 2026-10-21

## Что сделано

Реализован первый рабочий вариант пользовательских функций из простейших —
не только проектные заметки, но и код.

### Язык функций

- Блочный формат в `.lvl`:
  `function` / `description` / `in` / `out` / `use` / `body` / `end`.
- Именованные параметры, выходы и временные переменные; присваивания
  `q = div a b` и деструктуризация `q, r = divmod a b`.
- Фиксированные выходы и один поток `T...` последним.
- `take`, `drop`, `first`, `rest`, `count` в теле.
- Перегрузки по типам входов; `use`-алиасы для выбора конкретной сигнатуры.
- Случайность и транзитивная стабильность: функция, вызывающая `rand`/`sumr`,
  становится нестабильной, и решатель перебирает её исходы.

### Типы и литералы

- `ResultSpec` у встроенных сигнатур: фиксированные результаты и поток.
- `canPass`: `natural` расширяется до `integer`, обратное — только проверяемо.
- Типизированные литералы `natural=2` / `integer=2`; голое `2` при наличии
  обоих типов даёт ошибку с подсказкой.
- Bare-литерал в теле функции по умолчанию `integer`; приведение к `natural`
  проверяется при присваивании выходу.

### Имена чисел

- `number natural 3 as x` — необязательная метка.
- Имя можно вводить вместо значения; в смешанном наборе отображается
  `x=3(natural)`.
- Решатель видит только значения: имена-метки не меняют пространство поиска.
  Имена-ресурсы (различать два одинаковых числа) оставлены на будущее.

### Консоль и файлы

- `--function` — интерактивный редактор: `name`, `description`, `in`, `out`,
  `use`, `body`, `list`, `validate`, `test`, `save`.
- Сохранение в `data/functions/<имя>.fn`.
- Загрузка функции в уровень: `function <имя> file <файл>`.

### Ошибки

- Структурные ошибки блока проверяются при загрузке и содержат имя функции и
  строку.
- Ошибки выполнения не роняют игру: `calc`, игра и решатель получают
  сообщение; `--check` отбрасывает неудачный исход.
- Полная статическая типизация тел, коды диагностики и стек вызовов — позже.

## Зачем

Это шаг к механикам Java-прототипа (`Function`, `FunctionMakerPanel`), но с
человекочитаемым текстовым форматом вместо Java-сериализации. Пользовательские
функции позволяют строить уровни из более крупных смысловых блоков и позже
использовать их в модах.

## Проверки

- `--check` по 78 штатным уровням: 77 решаемы, уровень 18 остаётся известным
  ограничением DFS.
- Временные уровни 992–999 проверяли: фиксированные выходы, потоки,
  `take`/`drop`/`first`/`rest`/`count`, перегрузки, алиасы к пользовательским
  функциям, случайность, имена и неоднозначные литералы. После проверки
  временные файлы удалены.
- Round-trip `load → save → load` сохраняет блоки функций и решаемость.

## Ограничения

- `sort`/`shuffle`, `if`/`bool`, несколько потоков, статическая проверка типов
  и полноценный AST не реализованы.
- `abs`/`not` остаются бинарными ради уровней 23, 44, 57.
- `take`/`drop`/`first`/`rest`/`count` доступны в телах функций, но не как
  обычные команды/функции уровня.
- Имена чисел не влияют на решатель.
