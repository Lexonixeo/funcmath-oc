# 0002. Функции и уровни в духе №19 ЕГЭ

**Статус:** идея
**Сложность:** средняя

## Суть

Игра уже тренирует «получи одно число из других». Чтобы сильнее помогать
подготовке к №19 ЕГЭ (теория чисел), можно добавить функции и цели, которые
встречаются в задачах на делимость, остатки, НОД/НОК и разложение на множители.

### Новые функции

| Функция | Смысл |
|---------|-------|
| `gcd a b` | наибольший общий делитель |
| `lcm a b` | наименьшее общее кратное |
| `digits a b` | сумма цифр числа `a` в системе счисления `b` |
| `divcnt a b` | количество делителей `a` (второй аргумент игнорируется) |
| `divsum a b` | сумма делителей `a` |
| `isprime a b` | 1, если `a` простое, иначе 0 |
| `spf a b` | наименьший простой делитель `a` |
| `lastdigit a b` | последняя цифра `a` в системе `b` |

У всех функций два аргумента, чтобы не менять формат уровня; «лишний»
аргумент можно игнорировать или использовать как основание системы счисления.

**Уточнение после сверки с Java.** `gcd` и `lcm` уже есть в Java-прототипе,
но отсутствуют в C++. Их реализация и пограничные случаи (`gcd(0,0)`,
`lcm(0,0)`) разобраны в 0024. Эта заметка остаётся про дополнительные
функции и уровни, а не про базовый паритет.

### Цели уровней

Сейчас цель — одно число. Этого достаточно для многих задач:

- получить `1` через `isprime` (проверка простоты);
- получить `0` через `mod` (делимость);
- получить НОД двух чисел;
- получить число с ровно четырьмя делителями (через `divcnt` → `4`).

Если захочется целей-свойств («сделай число кратным 3», «получи простое
число»), формат `.lvl` можно расширить:

```
goal divisible 3
goal prime
goal divisors 4
```

Но начинать проще с числовых целей — они уже поддерживаются.

Несколько числовых целей и цели-свойства — разные расширения. Список
`answer` с проверкой по мультимножеству описан в 0021; `goal prime` требует
предиката и отдельного решателя, поэтому откладывается.

### Режим теории

Команда `theory gcd`, `theory mod`, `theory div` — короткая справка:
определение, пример, свойства, типичные ошибки. Это дёшево в реализации и
хорошо сочетается с подсказками.

## Зачем

- Прямое попадание в цель пользователя: подготовка к №19 и понимание
  операций, а не только «угадывание».
- Новые функции дают новые типы рассуждений: «на что делится», «сколько
  делителей», «какой остаток».
- Теория рядом с практикой помогает тем, кто впервые видит эти операции.

## Эскиз реализации

- Добавить операции в `src/Functions.cpp` и описания в
  `data/functions.txt`.
- Реализовать `gcd` через алгоритм Евклида, `digits` — циклом по основанию,
  `divcnt`/`divsum` — перебором до `sqrt(a)` (числа в игре небольшие).
- Добавить 5–10 уровней, проверить их через `--check`.
- Для `theory` — таблица текстов в `Level.cpp` или отдельный
  `data/theory.txt`.

## Что затронет

`Functions.{h,cpp}`, `Function.*` (если появятся функции с одним аргументом),
`data/functions.txt`, `data/levels/`, `Level.cpp`, `README.md`.

## Риски

- `divcnt`/`divsum` на больших числах могут быть медленными; нужны ограничения.
- Новые функции не должны попадать в генератор случайных уровней, пока для них
  нет хороших шаблонов.
