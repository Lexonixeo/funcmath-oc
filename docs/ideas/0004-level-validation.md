# 0004. Проверка и линт уровней

**Статус:** идея
**Сложность:** низкая

## Суть

Добавить режим `--validate N` (или `--lint`), который проверяет уровень до
публикации и печатает отчёт:

- корректно ли разобран `.lvl` (числа, цель, функции);
- нет ли цели среди стартовых чисел (иначе уровень проходится сам);
- все ли имена функций известны;
- известны ли поведения скрытых функций;
- достигается ли цель (запуск решателя с запасом по времени);
- за сколько ходов достигается минимум;
- есть ли решение в 1 ход (предупреждение «слишком просто»);
- нет ли дубликатов имён функций;
- не слишком ли большие числа (риск переполнения при `mul`/`pow`).

Пример отчёта:

```
Уровень 60: OK
  цель: -25
  минимум ходов: 3
  решений в 1 ход: нет
  скрытые функции: A=five, B=neg2
  предупреждений нет
```

`--author` может вызывать эту проверку автоматически и не сохранять уровень,
если он нерешаем (или спрашивать подтверждение).

## Зачем

В раннем прототипе был уровень 60 с недостижимой целью 15 — без решателя это
заметить было нельзя. Линт закрывает этот класс ошибок и помогает
поддерживать качество новых уровней.

## Эскиз реализации

- Вынести общую проверку в `LevelStore` или отдельный `Validator`.
- Переиспользовать `Solver` с большими лимитами.
- Добавить флаги: `--validate N`, `--validate-all`, `--strict`
  (считать предупреждения ошибками).
- В `--author` после ввода данных запускать проверку и показывать отчёт.

## Что затронет

`src/main.cpp`, новый `Validator.{h,cpp}` или
`LevelStore.{h,cpp}`, `LevelGenerator.cpp`, `README.md`.

## Риски

- Для уровней с `rand` проверка «решаем» означает «решаем при удачном исходе»;
  это нужно явно писать.
- Лимиты решателя могут давать ложное «не найдено»; в отчёте нужно отличать
  «нерешаем» от «поиск прерван».
