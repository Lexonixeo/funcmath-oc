# 0020. Правила уровня и лимиты функций

**Статус:** идея
**Сложность:** средне-высокая

## Что есть в Java, но нет в C++

В Java у уровня есть `DLRules`:

```java
record DLRules(
    boolean allowBack,
    boolean allowCalc,
    boolean infinityNumbers,
    boolean infinityFunctions)
```

Кроме того, у пользовательской функции есть `remainingUses`: при вызове она
тратит одно использование, а при `infinityFunctions = true` счётчик не
уменьшается. В C++ сейчас:

- `Level` не хранит правил уровня;
- `back` и `calc` доступны всегда;
- аргументы всегда удаляются из набора;
- у `Fn` нет счётчика использований, поэтому лимит функций выразить нельзя;
- `Solver` не знает ни о тратах чисел, ни о тратах функций.

Это не просто поля для красивого вывода. `infinityNumbers` и лимит функций
меняют пространство состояний, которое перебирает решатель. Поэтому заметка
вынесена отдельно, а не спрятана в 0005 или 0012.

## Предлагаемый формат

Правила уровня можно хранить прямо в `.lvl`:

```text
name Не тратить числа
rule allowBack false
rule allowCalc false
rule infinityNumbers true
rule infinityFunctions false
```

Для известной функции лимит можно задавать в строке уровня:

```text
function sum uses 3
```

Для пользовательской функции — внутри блока, рядом с `in`/`out`:

```text
function twice
  uses 2
  in a: natural
  out b: natural
  body
    b = sum a a
end
```

Точный синтаксис нужно выбрать при реализации; важно, чтобы старые `.lvl`
без `rule`/`uses` читались как раньше. Значения по умолчанию должны совпадать
с текущим поведением:

```text
allowBack         true
allowCalc         true
infinityNumbers   false
infinityFunctions true (в текущей C++-модели лимита нет)
```

## Семантика

### `allowBack`

Запрещает команду `back`. На решение уровня это не влияет, но влияет на
интерфейс и на то, можно ли отменить неудачный ход. `history` при этом может
продолжать храниться: запрет касается только команды, а не самой истории.

### `allowCalc`

Запрещает `calc`. В Java `calc` всегда вызывает функции с
`infinityFunctions = true` и не тратит числа уровня. Это стоит сохранить:
калькулятор — отдельный режим, а не ход в уровне.

### `infinityNumbers`

Если включено, аргументы выражения не удаляются из набора. Это режим
«калькулятора»: одно и то же число можно использовать сколько угодно раз.
В истории Java этот режим шёл вместе с отключением `calc`/`back`, но в текущей
модели это три независимых флага.

Нужно отдельно решить:

- считается ли уровень пройденным, если цель уже была в стартовом наборе;
- можно ли получить бесконечное число результатов и как это ограничивать;
- как `infinityNumbers` взаимодействует с именами чисел и типами.

### `infinityFunctions`

Если включено, счётчики функций игнорируются. Если выключено, каждый успешный
вызов уменьшает `remainingUses`; вызов при нуле — ошибка. В Java счётчик
уменьшается после успешного `compute`, а неудачный вызов состояние не меняет.
Калькулятор (`calc`) использует бесконечный режим независимо от правил уровня.

Для решателя это означает, что в ключ состояния нужно добавить счётчики всех
функций с конечным лимитом. Иначе DFS будет считать различные по ресурсам
состояния одинаковыми. При копировании истории счётчики тоже нужно копировать.

## Отображение

- функция с лимитом печатается как `sum (3)` или `sum (3/3)`;
- бесконечная — `sum (inf)`;
- в `history` и `hint` ход должен показывать, сколько осталось;
- в `--check` отчёт может содержать число использований функций.

## Зачем

- появляются уровни с ресурсом: «у тебя только два вызова `mul`»;
- можно делать уровни-калькуляторы, где числа не тратятся;
- можно запретить откат и калькулятор в обучающих или экзаменационных уровнях;
- это делает авторские уровни ближе к Java-прототипу, не требуя GUI.

## Что затронет

`src/LevelStore.*` (парсинг и сохранение правил/`uses`), `src/Level.*`
(проверка команд, расход чисел и функций), `src/Function.*` (счётчик и
копирование), `src/Solver.*` (ключ состояния и лимиты), `src/LevelGenerator.cpp`
(мастер уровней), `docs/game.md`, `docs/level-authoring.md`, `data/levels/`.

## Риски

- количество состояний может сильно вырасти: счётчики функций добавляют
  измерения в DFS;
- нужно аккуратно определить, что считается «успешным» вызовом при ошибке
  типа или домена;
- `infinityNumbers` может сделать уровень тривиальным, если цель уже есть в
  наборе;
- старые уровни не должны измениться из-за новых значений по умолчанию.

  могут распространяться лимиты.
